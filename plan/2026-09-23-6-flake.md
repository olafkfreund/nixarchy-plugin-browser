# Plan: Package the plugin as a flake for declarative install on nixarchy

This plan is self-contained; it carries every approved decision.

**Decisions**

- **Layout.** A new `flake.nix` in `olafkfreund/nixarchy-microvm`'s shape:
  nixpkgs `nixos-unstable`, systems `x86_64-linux` and `aarch64-linux`.
- **`packages.<system>.plugin`** (also `default`) is a `runCommand` that
  **copies** an explicit list:
  - files: `manifest.json`, `qmldir`, `LICENSE`, `README.md`, `CHANGELOG.md`,
    `Model.js`, `BarWidget.qml`, `Menu.qml`, `BrowserView.qml`,
    `BrowserState.qml`, `ShortcutSheet.qml`;
  - directories: `bin/`, `lib/`, `hypr/`.

  It never links, because the validator refuses symlinks. `tests/`,
  `install.sh`, `uninstall.sh`, `docs/` and the `intent/`, `spec/`, `plan/`
  documents are left out.
- **`packages.<system>.cli`** holds three wrappers, `omarchy-plugin-audit`,
  `omarchy-plugin-browser` and `nixarchy-plugin-fix`, each
  `exec bash <plugin>/bin/<tool> "$@"`. The flake adds no runtime
  dependencies; the scripts keep their root-owned PATH.
- **`homeManagerModules.default`** adds `programs.nixarchy-plugin-browser.keybinding`,
  default `"SUPER + ALT + U"`, type `nullOr (strMatching "[A-Z0-9_ +]+")`. It
  writes `.config/hypr/plugin-browser-binds.lua` from `./hypr/plugin-browser-binds.lua`
  with the chord substituted.
- **`checks.<system>.default`** runs on the built package:
  - the three test suites;
  - nixarchy's exact pacman/yay grep, which must find nothing;
  - a check that the package has no symlinks and no tests or documents;
  - a `--help` smoke run of each CLI wrapper.
- **The pacman check.** In `lib/omarchy-plugin-scan.sh`, `pacman` becomes
  `pac[m]an` and `yay` becomes `y[a]y` in the two detector lines, each with a
  comment saying why. `tests/scan-nix.sh` adds `yay -S bar` and asserts that
  `imperative-pkg` and the `package-manager` CAP fire for both words.
- **Store installs and updates.** When `updateInfo.git_managed === false`, the
  update popup shows "Installed through Nix: update with
  `nix flake update nixarchy-plugin-browser` and rebuild." in place of the
  Update… button. Later stays. `lib/update.sh` is unchanged.
- **Docs.** The README gets an "Install with Nix" section.
- **Not in this repo:** switching `nixos_config` to declare the plugin is that
  repo's later change.

## Steps

1. `lib/omarchy-plugin-scan.sh`: rewrite the two pattern lines and add their
   comments. `tests/scan-nix.sh`: add `yay -S bar`, plus assertions for
   `imperative-pkg` and the `package-manager` CAP on both words.
   → verify:
   - `bash tests/scan-nix.sh` prints `ok`;
   - nixarchy's grep over the plugin's runtime files finds nothing;
   - a mutation that breaks `pac[m]an` makes the test fail.
2. `BarWidget.qml`: the store-install branch of the update popup, keyed on
   `updateInfo.git_managed === false`.
   → verify: qmllint shows 0 `[syntax]`, and `omarchy-plugin-validate .`
   passes. The desktop check is G1's.
3. `flake.nix`: `packages` (plugin, cli, default), `homeManagerModules.default`
   and `checks`. Generate `flake.lock` with `nix flake lock`.
   → verify:
   - `nix flake check` passes;
   - `nix build .#plugin` has no symlinks and no
     `tests/intent/spec/plan/install.sh`;
   - `nix build .#cli`, then `result/bin/omarchy-plugin-audit crmne.hyprmoncfg --json | jq -r .outcome`,
     gives `review-required`.
4. **Real-consumer check.** Evaluate and build p620's Home Manager plugin
   derivation with `programs.nixarchy.plugins.plugin-browser.src` set to this
   flake's package. That means a throwaway `nixos_config` worktree, never
   committed, with a temporary input
   `nixarchy-plugin-browser.url = "path:<this repo>"`. Build only the
   `nixarchy-plugin-plugin-browser` validation derivation (nixarchy's
   `validatedPlugins`), and deploy nothing.
   → verify: that derivation builds, meaning `omarchy-plugin-validate` and
   nixarchy's pacman check both pass on the real package.
5. `README.md`: an "Install with Nix" section and the Layout additions.
   `CHANGELOG.md`: a 0.4.0 bullet.
   → verify: every path it mentions exists, and the snippet matches the flake's
   output names.
6. Push `feat/6-flake` and open a PR linking the three artifacts, closing #6.
   Its base is `feat/4-qml-panel` (stacked), retargeted to `master` once #5
   merges.

## Deviations recorded during implementation

- **The validator is not run inside `nix flake check`.** The spec lists it
  there, but `omarchy-plugin-validate` ships only with nixarchy, not nixpkgs.
  Running it in the check would need nixarchy as an input just for that, which
  microvm's flake avoids. It runs in step 4 instead, through nixarchy's own
  validation derivation, which is the stricter test because it is exactly
  what a consumer runs.

- **`catalog-list.sh` and the CLI `--help` smoke run are not in the sandbox
  check either.** Both run scripts that pin their PATH to
  `/run/current-system/sw/bin`, deliberately, because only root-owned tools
  are trusted. That directory does not exist in the Nix build sandbox. They
  run on the real system in step 3 instead: `tests/catalog-list.sh` gives
  `ok`, and the `cli` wrappers audit `crmne.hyprmoncfg` from the store copy
  (`review-required`). The sandbox check still runs `scan-nix.sh` and
  `model-check.mjs` against the packaged files; the log shows `ok` for both.

## Rollback

- Before merge: close the PR and delete the branch.
- After merge: revert the commits. `install.sh` and `omarchy plugin add` never
  depended on the flake.
- Consumers pin the flake in their lock, so a bad release is undone by
  reverting their lock bump.
