# Plan: Run inside the Omarchy shell as a keyboard-driven panel with its own keybinding

This plan is self-contained. It carries every approved spec decision.

**Decisions**

- The plugin becomes `kinds: ["menu", "bar-widget"]`, with
  `entryPoints: {menu: "Menu.qml", barWidget: "BarWidget.qml"}`, version
  0.4.0, and the id stays `io.github.olafkfreund.nixarchy-plugin-browser`.
- **Files follow `nixarchy.devenv`:**
  - `qmldir` (`singleton BrowserState 1.0 BrowserState.qml`);
  - `BrowserState.qml` (the singleton);
  - `BrowserView.qml` (the keyboard view);
  - `ShortcutSheet.qml` (`?`);
  - `Menu.qml`, the full-screen `PanelWindow`: Overlay layer, exclusive
    keyboard, scrim, and a `BorderSurface` card at `uiScale` 1.45. It
    implements `open(payloadJson)`, `close()`, `toggle()` and `opened`.
- **`Model.js` (added in this plan).** Pure functions: `filterRows`,
  `isSafeId`, `parsePayload`, `verdictLabel`. It is kept free of QML types so
  `node` can test it. The spec's file table did not list it, but devenv has
  the same file.
- **The catalog never reaches the shell whole.** `lib/catalog.sh` becomes
  the one home of the bounded, cached catalog fetch; the audit and the TUI
  both source it. `catalog.sh list` prints a jq projection of community
  plugins with `{id, name, author, category, stars, tags, badge, description, repo, installCommand, installAvailable}`,
  sorted by stars. The shell parses that list once per open. Filtering is a
  JS substring match 80 ms after the last keystroke. It moves to a
  `WorkerScript` if a filter takes more than 16 ms.
- **Actions in the detail pane:**
  - opening the details and `a` run `bin/omarchy-plugin-audit <id> --json`
    through `Process`, and show the security and NixOS verdicts;
  - `e` / `f` start `omarchy-launch-tui --app-id=TUI.float … nixarchy-plugin-fix <id> --mode explain|fix`
    with `execDetached`;
  - `i` asks y/n in the panel, then runs `omarchy-plugin-audit <id> --install`
    in a `Process`;
  - `c` runs `wl-copy <installCommand>` (argv);
  - `o` runs `omarchy launch browser <repo>`, only for `https://github.com/…`
    repos.
- **Keys:** as in the spec's table. Type to search; ↑ ↓ or Ctrl+J / Ctrl+K to
  move; Enter; Ctrl+R; Esc; in the details, a e f i c o, j k and Esc / ←; `?`.
- **Payload:** `{"id": …}` opens that plugin's details, `{"query": …}` opens
  with a search typed. Anything else, or bad JSON, opens the list.
- **Security:**
  - every marketplace or report `Text` sets `textFormat: Text.PlainText`;
  - ids are checked with `isSafeId` before any argv;
  - fixed absolute argv, no `sh -c`, and a root-owned PATH in `environment`;
  - `JSON.parse` failures become an error line, never an exception.
- **Bar widget:** a left click toggles the surface through
  `omarchy-shell shell toggle <id> '{}'` (argv). The update dot and popup
  stay; the popup's "Browse plugins" also toggles the surface. **A right
  click opens the gum TUI in a terminal**, which settles the spec's "TUI
  reachable from the bar button". The TUI stays the terminal fallback.
- **Keybinding:** Super+Alt+U, description "Plugin browser". The repo ships
  `hypr/plugin-browser-binds.lua` for manual installs.
- **Machine wiring,** in `~/.config/nixos` (`olafkfreund/nixos_config`),
  copying `hosts/common/nixos/omarchy-gog.nix`:
  - a new module `hosts/common/nixos/omarchy-plugin-browser.nix` that declares
    `programs.nixarchy.menu.extraEntries."setup.plugin.add"` (icon 󰖟, label
    "Add Plugin", action `omarchy-shell shell toggle io.github.olafkfreund.nixarchy-plugin-browser '{}'`)
    and `home-manager.users.olafkfreund.home.file.".config/hypr/plugin-browser-binds.lua".text`;
  - an import from `hosts/p620/nixos/nixarchy.nix`;
  - one `pcall(require, "hypr.plugin-browser-binds")` line in the user-owned
    `~/.config/hypr/bindings.lua`, added only with consent.
- **Verification gate:** the QML cannot run in the build sandbox (no shell
  IPC), so the desktop checklist (G1) must pass before merge.

## Steps

### Phase 1: catalog helper (this repo)

1. `lib/catalog.sh`: move the following out of both `bin/` scripts, where they
   are duplicated today:
   - the `CATALOG_URL`, `CACHE_DIR`, `CATALOG`, `CACHE_TTL` and
     `CATALOG_MAX_BYTES` settings;
   - `catalog_usable`, `download_catalog`, and a `fetch_catalog [--force]`.

   It is sourced for those functions, or run as `catalog.sh list [--refresh]`.
   The browser sets `CATALOG_RUNNER` (gum spin) before sourcing it; the audit
   calls curl directly.
   → verify:
   - `bin/omarchy-plugin-audit crmne.hyprmoncfg --json | jq .outcome` still
     gives `review-required`;
   - `bash -n` passes;
   - the TUI still starts under `script` (the same drive as #1).
2. `tests/catalog-list.sh` builds a fixture catalog with three plugins: two
   community, one not, with different stars. It runs `catalog.sh list` against
   it through `CATALOG=<fixture>` and a fresh cache, and asserts the fields,
   the star order, and that the non-community plugin is gone.
   → verify: it prints `ok`, and a mutation that drops the community filter
   makes it fail.
3. Measure on the real catalog, and record the numbers in the commit message:
   the `list` output size, its run time, and `node` timing of `JSON.parse`
   plus `Model.filterRows` over it (the function comes from Q2; measured
   together with Q2).

### Phase 2: the QML plugin (this repo)

Q1. `manifest.json`: the kinds and entry points above, version 0.4.0. Add
    `qmldir`.
    → verify: `omarchy-plugin-validate .` exits 0.
    *As built:* the validator refuses an entry point whose file does not exist
    yet, so Q1 is committed together with Q6 (`Menu.qml`).
Q2. `Model.js`: `filterRows(rows, query)` (case-insensitive over name, id,
    author, category and tags, keeping the star order), `isSafeId`,
    `parsePayload` and `verdictLabel`. `tests/model-check.mjs` loads it in node
    and asserts the cases: an empty query returns everything, matches on tags
    and author, unsafe ids are rejected, and bad JSON gives `{}`.
    → verify: `nix run nixpkgs#nodejs -- tests/model-check.mjs` prints `ok`.
    Filter timing is under 16 ms on the real list; if not, switch to a
    `WorkerScript` in Q3.
Q3. `BrowserState.qml` (the singleton) holds `rows`, `loading`, `error`,
    `report`, `auditing`, `installOutput` and `installing`. It has:
    - a `Process` for the catalog (`list` / `list --refresh`), one for the
      audit, and one for install;
    - `execDetached` for the agent, copy and open.

    Paths come from `Qt.resolvedUrl`, as `BarWidget.qml` does, and every
    command is an absolute argv.
    → verify: review against `DevenvState.qml`; `grep` shows no `sh -c` and no
    bare command names in argv.
Q4. `BrowserView.qml` provides:
    - a search `TextInput` (focused), a `ListView` of rows (badge, name,
      author, category, stars);
    - the detail pane (description, repo, verified commit, audit spinner or
      report sections, NixOS section), and the y/n confirm bar;
    - `Keys` handlers for the spec's table; all data `Text` is `PlainText`.

    → verify: review. `grep -c 'PlainText'` equals the number of data `Text`
    items.
Q5. `ShortcutSheet.qml` lists every key from the table, toggled with `?`.
    → verify: review. The keys match the table.
Q6. `Menu.qml` is the devenv surface with `BrowserView` inside, calling
    `open(payloadJson)` through `Model.parsePayload`.
    → verify: review side by side with devenv's `Menu.qml`.
Q7. `BarWidget.qml`:
    - `launch()` toggles the surface (argv
      `["/run/current-system/sw/bin/omarchy-shell", "shell", "toggle", "<id>", "{}"]`);
    - a right click opens the TUI (the old `launch()` argv);
    - the update popup's "Browse plugins" toggles the surface.

    → verify: review. `omarchy-plugin-validate .` passes.
Q8. `hypr/plugin-browser-binds.lua`, in devenv's form, including the
    `pcall` explanation.
    → verify: `nix run nixpkgs#lua -- -e 'o={bind=function(...) end}; dofile("hypr/plugin-browser-binds.lua")'`
    exits 0.
Q9. Documentation:
    - `README.md`: the panel, the keys, Super+Alt+U, the menu row, the
      Nix-module snippet, the manual route (copy the `.lua` file and add the
      `pcall` line), and "enable the plugin".
    - `CHANGELOG.md` 0.4.0.
    - `install.sh --plugin` mentions the keybinding and the menu snippet.

    → verify: every path the README mentions exists.
Q10. Static pass:
     - `bash -n`, shellcheck (no new warnings), `tests/*.sh`, node check;
     - `qmllint` from `nixpkgs#kdePackages.qtdeclarative` on the new `.qml`
       files, for syntax errors only (unresolved `qs.*` imports are
       expected);
     - `omarchy-plugin-validate .`.

     → verify: all clean. Record the qmllint output in the commit.

### Phase 3: machine wiring (`~/.config/nixos`, with consent at M1)

M1. In `~/.config/nixos`, follow that repo's own contribution rules. If they
    require an issue or artifacts, open or write them there first. Add
    `hosts/common/nixos/omarchy-plugin-browser.nix` (a copy of
    `omarchy-gog.nix`'s shape, with the entries above) and import it from
    `hosts/p620/nixos/nixarchy.nix`. Commit it on a branch there.
    → verify: `nix eval .#nixosConfigurations.p620.config.programs.nixarchy.menu.extraEntries --json | jq '."setup.plugin.add"'`
    shows the new action.
M2. Show the user the one-line `pcall` addition for `~/.config/hypr/bindings.lua`,
    and add it only after they say yes.
    → verify: `grep -c 'hypr.plugin-browser-binds' ~/.config/hypr/bindings.lua`
    is 1.
M3. The user deploys the system (their command) and installs and enables the
    plugin: `./install.sh --plugin`, then
    `omarchy plugin enable io.github.olafkfreund.nixarchy-plugin-browser`.
    The build sandbox cannot reach the shell IPC that these need.

## Rollback

- **This repo:** revert the branch, or `git revert` the merge range. 0.3.0
  keeps working, because the CLIs and TUI are unchanged in behaviour.
- **The config repo:** remove the import of `omarchy-plugin-browser.nix` and
  redeploy. **Add Plugin** returns to `omarchy-plugin-add`, and the binds
  file disappears. The `pcall` line in `bindings.lua` then does nothing, as
  designed.
