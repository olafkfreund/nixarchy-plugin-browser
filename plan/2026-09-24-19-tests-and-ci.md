# Plan: Run the tests on every pull request, and test the audit's gates

This plan is self-contained; it carries every approved decision.

**Decisions**

- **Runners:** GitHub-hosted `ubuntu-24.04` only. No pull request code runs
  on p620. CI builds and checks `x86_64-linux` only; `aarch64-linux` stays
  declared in the flake and is not built.
- **No binary cache for now.** Add `DeterminateSystems/magic-nix-cache-action`
  or Cachix only if runs get slow.
- **Dependabot** for GitHub Actions only, weekly.
- **Two tiers, one harness.** Every test is a standalone file that prints
  `ok` and exits 0, or names the first failure and exits non-zero. Each file
  has a tier line near the top: `# tier: hermetic` or `# tier: host`
  (`// tier: …` in `.mjs`).
  - **hermetic** needs only the caller's `PATH` and the repository, and runs
    inside `nix flake check`.
  - **host** runs a script that pins `PATH` to `/run/current-system/sw`. It
    runs on a NixOS machine, or on the CI runner after the shim step.
  - `tests/run.sh [hermetic|host|all]` (default `all`, about 15 lines of
    bash) runs every `tests/*.sh` and `tests/*.mjs` whose tier matches, with
    `bash` or `node`. It prints `PASS <name>` or `FAIL <name>` plus the test's
    output, runs them all, and exits 1 if any failed. A file with no tier
    line fails the run.
- **Tiers:** `scan-nix.sh` and `model-check.mjs` are hermetic.
  `preview.sh`, `catalog-list.sh`, and the new `audit-gates.sh` and
  `update.sh` are host.
- **`preview.sh` runs as a host-tier CI step outside Nix.** This deviates on
  purpose from the intent's outcome, which put it in `nix flake check`. It
  runs `bash lib/catalog.sh preview …`, which exports the pinned `PATH`
  (`lib/catalog.sh:134`), so it is not hermetic. The approver accepted this.
- **`lib/catalog.sh`, `lib/update.sh` and `bin/omarchy-plugin-audit` keep
  their pinned `PATH`.** No production code changes in this issue. Tests use
  only the existing knobs.
- **If bwrap cannot run on the runner, the sandboxed audit cases stay red.**
  There is no `--no-sandbox` fallback for them.
- **Scope split.** #19 lands first. #15, #17 and #18 then add their tests by
  dropping one file with a tier line into `tests/`, with no other edit.
  - #19 tests only the existing `--export-tree` symlink refusal.
  - #15 owns the spoofed-VALIDATE test and every other symlink and local
    `--install` case.
  - #18 owns the hostile catalog-row tests, `--category` bounds, and the
    preview off-switch that fails open when `jq` cannot run
    (`previews_enabled`, `lib/catalog.sh:80`).
  - #17 owns panel regressions (hermetic `.mjs`).
- **Fixture rules for every host test:** `mktemp -d` plus `trap` cleanup,
  `CATALOG=` set to a fresh fixture, local directories or `file://`
  repositories as targets, no network.
- **`check`** becomes a required status on `master` only after it has been
  green on a few pull requests.

## Steps

1. `tests/run.sh`: new harness, as in the decisions. The tier is read with
   `grep -m1 -oE '^(#|//) tier: (hermetic|host)'` on the file.
   → verify by `bash tests/run.sh` printing `FAIL` for each of the four
   existing tests (no tier line yet) and exiting 1.

2. `tests/scan-nix.sh`, `tests/model-check.mjs`, `tests/preview.sh`,
   `tests/catalog-list.sh`: add the tier line under the header comment. Change
   nothing else.
   → verify by `bash tests/run.sh hermetic`, `bash tests/run.sh host` and
   `bash tests/run.sh` each printing only `PASS` lines and exiting 0 on this
   NixOS machine. Then a scratch `tests/zz.sh` with no tier line makes
   `run.sh` exit 1 and name it. Delete the scratch file.

3. `flake.nix` `checks.<system>.default`: replace the two explicit test lines
   with `bash work/tests/run.sh hermetic`. Keep the package assertions and
   the pacman/yay grep as they are, and add `bash` to `nativeBuildInputs` if
   the builder lacks it.
   → verify by `nix flake check -L` passing, and by a throwaway `exit 1` at
   the top of `tests/scan-nix.sh` turning `default` red with
   `FAIL scan-nix.sh` in the log. Revert the throwaway.

4. `flake.nix` `checks.<system>.files`: a `runCommand` over `self`. For each
   top-level `*.qml` and `*.js`, plus `qmldir` and `manifest.json`, the file
   must exist in `${plugin}`, or the check prints its name and fails. For
   `bin`, `lib` and `hypr`, `diff -r ${self}/<d> ${plugin}/<d>`.
   → verify by `nix build .#checks.x86_64-linux.files`, then by removing
   `./Menu.qml` from `files` in a throwaway edit: the check fails and prints
   `Menu.qml`. Revert.

5. `flake.nix` `checks.<system>.hm-module`: `lib.evalModules` with
   `self.homeManagerModules.default` and a stub module declaring only
   `home.file` as `attrsOf (submodule { options.text = mkOption { type = str; }; })`.
   Assert at evaluation time:
   1. the default writes `.config/hypr/plugin-browser-binds.lua` containing
      `SUPER + ALT + U`;
   2. `keybinding = "SUPER + SHIFT + P"` replaces the chord;
   3. `keybinding = null` writes no file;
   4. `builtins.tryEval` of the forced `keybinding = "U\"); os.execute(\""`
      result is `{ success = false; }`.

   The output is a `writeText` holding the four results. No home-manager
   input is added.
   → verify by `nix build .#checks.x86_64-linux.hm-module`, then by changing
   the default chord in the module in a throwaway edit: evaluation fails.
   Revert.

6. `tests/audit-gates.sh` (host): new. Each case builds its fixture under
   one `mktemp -d`, runs `bin/omarchy-plugin-audit … --json` with
   `CATALOG=<fresh fixture>`, and asserts the exit code and one field or
   message:

   | Gate | Fixture | Expected |
   | --- | --- | --- |
   | FIND → 20 (sandboxed) | local plugin with `eval(x)` in a QML file | exit 20, `outcome == "needs-fixes"` |
   | VALIDATE fail → 20 | clean plugin, `--no-sandbox`, `OMARCHY_BIN=<dir>` holding an `omarchy-plugin-validate` that exits 1 | exit 20, `manifestValidate == "fail"` |
   | clean → 0 (sandboxed) | clean plugin, `OMARCHY_BIN=<dir>` with a validator that exits 0 | exit 0 |
   | file limit | `AUDIT_STAGE_MAX_FILES=2`, local plugin with 3 files | exit 3, message names the file count |
   | byte limit | `AUDIT_STAGE_MAX_BYTES=10`, the same plugin | exit 3, message names the size |
   | deadline | `AUDIT_STAGE_DEADLINE_SEC=0`, a `file://` git repository | exit 3, `deadline` in the message |
   | symlink export | local plugin with a symlink, `--export-tree <new dir>` | exit 20, `<new dir>` does not exist afterwards |

   Nothing is added to `bin/omarchy-plugin-audit`. If a gate does not behave
   as shown (for example, the clean sandboxed case cannot reach a fixture
   validator because the sandbox fixes `OMARCHY_BIN`, or the local path
   follows the symlink before `--export-tree` sees it), record it here:
   - a clean-case mismatch is resolved in the test by asserting what the
     audit really does with the real path, and this plan is updated in the
     same commit;
   - a symlink-gate bug is not tested here. It is reported on #15, and #15
     writes the regression test.

   → verify by `bash tests/run.sh host` passing, then by each throwaway
   break turning exactly its case red: make the audit ignore
   `AUDIT_STAGE_MAX_FILES`, then `AUDIT_STAGE_MAX_BYTES`; force `OC_EXIT=0`;
   delete the `--export-tree` symlink `die` (lines 405 and 411); drop the
   deadline comparison. Never committed.

7. `tests/update.sh` (host): new. `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` in a
   `mktemp -d`; `update-check.json` seeded with `checked` = now, so `fetch`
   is never reached. Assert:
   - `check` gives `available: true` when the cached `latest` is newer than
     the installed version, `false` when equal, `false` when older;
   - `ver_gt` orders `0.10.0` above `0.9.0` (through `check` with those
     versions);
   - `dismiss 1.2.3` stores `dismissed == "1.2.3"`;
   - `"update_check": false` gives `enabled: false`, and the cache file's
     checksum is unchanged.

   `run` and `terminal` are left out.
   → verify by `bash tests/run.sh host` passing, then a throwaway inverted
   `ver_gt` turning it red. Never committed.

8. Review the new tests for network use: `grep -nE 'https?://|git@'
   tests/audit-gates.sh tests/update.sh` shows no target that is not a
   fixture or `file://`.
   → verify by the grep output being empty or fixture-only.

9. `.github/workflows/ci.yml`: new, exactly as in the spec: `pull_request`
   (never `pull_request_target`), `push` to `master`, `workflow_dispatch`;
   `permissions: contents: read`; concurrency `ci-${{ github.ref }}` that
   cancels only pull request runs; one job `check` on `ubuntu-24.04`,
   `timeout-minutes: 20`, no path filters. Steps:
   1. `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`
      with `persist-credentials: false`;
   2. `cachix/install-nix-action@13d8dd58da0234aa297dedd986986ccb8e7f3e24 # v31.11.1`;
   3. `nix flake check -L`;
   4. the shim: `sysctl kernel.apparmor_restrict_unprivileged_userns=0`,
      then a root-owned `/run/current-system/sw/bin` of symlinks to bash,
      coreutils, findutils, gnugrep, gnused, gawk, jq, file, git, curl,
      bubblewrap, util-linux and diffutils, built with
      `nix build --inputs-from .` from the locked nixpkgs;
   5. `bash tests/run.sh host`.

   → verify locally first by
   `nix run nixpkgs#actionlint -- .github/workflows/ci.yml` passing and
   `act -n -j check` (dry run; `act` is installed) listing the steps. A real
   `act` run is not the proof: its container has no Nix, sudo sysctl or
   AppArmor like the hosted image.

10. `.github/dependabot.yml`: new, `github-actions`, directory `/`, weekly.
    → verify by the file parsing (`nix run nixpkgs#yq-go -- . .github/dependabot.yml`)
    and, after merge, step 14.

11. `.github/workflows/pages.yml`: pin by SHA on the current majors, with a

    - `actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0`
      (both jobs, each with `persist-credentials: false`);
    - `actions/configure-pages@983d7736d9b0ae728b81ab479565c72886d7745b # v5.0.0`;
    - `actions/jekyll-build-pages@44a6e6beabd48582f863aeeb6cb2151cc1716697 # v1.0.13`;
    - `actions/upload-pages-artifact@56afc609e74202658d3ffba0e8f6dda462b719fa # v3.0.1`;

    Concurrency becomes `group: pages-${{ github.ref }}` with

    Nothing else changes.
    → verify by actionlint passing, and by
    `grep -n 'uses:' .github/workflows/*.yml` showing only 40-character SHAs,

12. Prove `ci.yml` on GitHub: push the branch and open a draft pull request.
    → verify by `gh pr checks --watch` showing `check` green, and in its log
    the flake check, the shim, and `PASS` for every host test including the

## Tests

- `bash tests/run.sh` on a NixOS machine: only `PASS` lines, exit 0.
- `nix flake check -L`: `default`, `files` and `hm-module` pass.
- Each throwaway break from steps 3 to 7 turns exactly its own check red.
- A tier-less file in `tests/` makes `tests/run.sh` exit 1.
- On the draft pull request: `check` green; a red push turns it red; a
  second push cancels the first run; a `docs/` change builds Pages without
  deploying.
- `grep -n 'uses:' .github/workflows/*.yml`: SHAs only, each with a version
  comment.

## Rollback

- Before merge: close the pull request and delete the branch.
- After merge: `git revert` the merge commit. No production code changed, so
  the plugin and CLI are unaffected.
- If `check` was already required and must be dropped:
  `gh api -X DELETE repos/olafkfreund/nixarchy-plugin-browser/branches/master/protection/required_status_checks`,
  or remove `check` from the contexts in the repository settings.
- If Pages misbehaves after the pin, revert `pages.yml` alone; the tag pins
  it replaces are in git history.
