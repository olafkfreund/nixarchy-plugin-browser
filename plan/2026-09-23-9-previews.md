# Plan: Show the marketplace preview image in the panel

This plan is self-contained; it carries every approved decision.

**Decisions**

- **Only the thumbnail.** The panel shows `previewThumbnail` (720×405), and only
  for the plugin whose details are open. There is no enlarge key, no
  pre-fetching, and the list stays text.
- **`lib/catalog.sh`:**
  - `list` gains `preview: (.previewThumbnail // "")`.
  - A new `catalog.sh preview <relpath>` prints a verified local file path
    and exits 0. Otherwise it exits non-zero with a one-line reason on stderr:
    exit 4 for "previews are off", 2 for a bad path, 3 for a failed fetch or
    check.
  - Its steps, in order:
    1. the off switch (`"previews": false` in
       `${XDG_CONFIG_HOME:-~/.config}/nixarchy-plugin-browser/config.json`);
    2. the path allowlist,
       `^assets/img/plugins/[A-Za-z0-9][A-Za-z0-9._-]{0,120}\.(webp|png)$`;
    3. a usable cache hit in `$CACHE_DIR/previews/<basename>`;
    4. curl against `https://plugins.omarchy.org/<relpath>` (https only,
       TLS 1.2+, 15 s, `--max-filesize 2 MiB`) into a `mktemp` file in
       `previews/`;
    5. a size check and a magic-byte check (RIFF+WEBP, or the PNG
       signature, matching the extension);
    6. `mv -f` into place, then prune `previews/` to 50 MiB, oldest first.
  - The directory is `chmod 700`. `preview_path_ok` and `preview_file_ok`
    are separate functions.
- **`Model.js`:** `parseRows` keeps `preview` only if it matches the same
  pattern. `previewArgv(root, relpath)` returns the argv, or `null`.
- **`BrowserState.qml`:** `previewFor`, `previewPath`, `previewing`, and
  `preview(row)` with one `Process`, where the newest request is queued.
  `previewPath` is accepted only on exit 0 and when it is an absolute path
  under the cache's `previews/` directory. Errors are not shown.
- **`BrowserView.qml`:** one `Image` at the top of the details.
  - `source` is set only when `previewFor === selected.id`;
  - `sourceSize: 720×405`, so decoding is bounded;
  - `asynchronous: true`, `cache: false`;
  - zero height until it is `Ready`.

  `openDetails` calls `BrowserState.preview(row)` next to `audit`.
- **Docs.** The README gets preview sections covering the source, the checks,
  the privacy note and the off switch. CHANGELOG 0.5.0; the manifest goes to
  0.5.0.

## Steps

1. `lib/catalog.sh`: `preview_path_ok`, `preview_file_ok`, `previews_enabled`,
   the `preview` subcommand, and the `preview` field in `list`.
   → verify:
   - `bash -n` passes and shellcheck adds no warnings;
   - `tests/catalog-list.sh` is extended for `preview` and passes.
2. `tests/preview.sh` (new, no network):
   - the path cases: the real path passes; `../x.webp`, `https://evil/x.webp`,
     `assets/img/plugins/x.webp?y`, `assets/img/other/x.webp` and
     `assets/img/plugins/x.svg` are rejected;
   - the file cases: a WebP header and a PNG header pass; text named `.webp`,
     an empty file, a file over the ceiling and a PNG named `.webp` are
     rejected;
   - the off switch: exit 4, "previews are off", and no file created under
     `previews/`.

   it fail.

   `tests/model-check.mjs`: add the path cases and an absolute-argv case.

## Deviations recorded during implementation

- **The off-switch test does not use "a PATH with no curl".** `catalog.sh`
  pins its own PATH when run directly, so a test PATH never reaches it. The
  test proves the same property instead: exit 4, the "previews are off"
  message, and nothing written under `previews/`. By construction, the
  switch is checked first, before any path, cache or network code.

## Rollback

- Revert the commits. `catalog.sh list` ignores the extra field in older
  panels, and the preview cache is plain files under `~/.cache`
  (`omarchy-plugin-audit/previews/`) that are safe to delete.
