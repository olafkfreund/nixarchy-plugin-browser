# Intent: a GitHub Pages site in nixarchy's style, with screenshots and a recording

## Problem

The Plugin Browser is described only by its README. nixarchy is about to
ship it as the panel behind Setup ▸ Plugins ▸ Add Plugin (nixarchy #913 /
#915), and nixarchy's manual points readers at each plugin's repository.
Other nixarchy panels have more than that: nixarchy-pkg has its own site
(https://olafkfreund.github.io/nixarchy-pkg/), built from nixarchy's own site
design, with a tour recording and numbered screenshots.

For this plugin a picture matters more than for most. What it does — a
searchable marketplace, a preview, two audit verdicts before anything is
installed, a disabled install, an agent that explains or fixes — is hard to
convey in prose, and nobody has seen it except on two machines. There are no
screenshots in the repo or in nixarchy's docs.

## Proposed outcome

- **A site at https://olafkfreund.github.io/nixarchy-plugin-browser/** that
  looks like nixarchy's site: the same layouts, stylesheet, fonts and logo
  treatment, adapted the way nixarchy-pkg adapted them. It has a landing page
  and a short manual (what it does, keys, the audit and its verdicts, the
  agent hand-off and its risk, installing on nixarchy or by hand, privacy and
  previews).
- **Real media from a nixarchy desktop:** numbered screenshots of each state
  (list, search, details with preview, both verdicts, the install confirm,
  the `e`/`f` terminal), plus one short tour recording (GIF, with WebM and a
  poster), captured on razer. Nothing private is shown.
- **nixarchy's docs reuse them:** the manual's Plugin Browser section shows
  the tour and two or three stills, as its GitHub Actions and Podman sections
  do.
- **The site is published by a workflow on push to master,** and pages that
  are not reachable from the navigation fail the check on a PR, as in
  nixarchy-pkg.

## Affected users and systems

- **This repo:** a new `docs/` tree (Jekyll: layouts, includes, assets, pages,
  images), a Pages workflow, and README links. The flake's `plugin` package
  is unaffected, because `docs/` is not in its file list; its check proves
  that.
- **GitHub settings:** Pages enabled for this repo with the workflow as its
  source. This is an outward-facing repository setting.
- **nixarchy:** `docs/manual/plugins.md` (and its `docs/img/`) gains the
  media and a link to the site. That is either PR #915 (#913) or a follow-up
  PR there.
- **razer:** the captures are taken there, under ai-mirror control granted
  by the owner, recorded, and announced on the bus.

## Constraints

- **The same design as nixarchy's site.** Reuse its files and adapt them;
  don't invent a new look. Keep the adaptation traceable (nixarchy-pkg's
  copies are the precedent).
- **Nothing private in any capture:**
  - no document paths (the menu search's Files section);
  - no browser profile or bookmarks;
  - no clipboard content;
  - no real tokens.
  Plugins shown are public marketplace entries.
- **Size:** images stay small (WebP for stills where nixarchy uses them, a
  GIF under a few MB), and nothing large goes into the plugin package.
- **nixarchy's docs rules apply there:** image paths, the manual row check,
  and its captions style ("Recorded on …").
- **Pages is a public, outward-facing setting,** and turning it on is the
  owner's call.
