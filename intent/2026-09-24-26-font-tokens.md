# Intent: The panel uses the same text sizes as the other nixarchy menus

## Problem

Issue #26 was filed from the nixarchy-flatsnap fix (olafkfreund/nixarchy-flatsnap#9,
PR #14) against `Menu.qml:27` `uiScale: 1.45`. Part of it is already done
on master, and part is not.

**Already fixed by #16 (PR #25):**

- The 1.45 multiplier and the `scale:` transform are gone. `grep -nE
  'textScale|uiScale|px\(' *.qml *.js` finds nothing on master.
- Every text size in the panel is a bare `Style.font.*` token, so it follows
  `[font] base-size` in `~/.config/omarchy/shell.toml` (`omarchy display text
  size`).
- The card title is already `Style.font.heading` (`BrowserView.qml:153`,
  detail name `:343`, `ShortcutSheet.qml:29`), and the search input is already
  `Style.font.title` (`BrowserView.qml:187`; the placeholder inherits it
  through `font: search.font`).

**What remains:**

- **Body text is one step below the family.** #16 moved caption text "two
  steps up" to `Style.font.subtitle` (13 px at base 12). flatsnap, and the
  sibling menus that follow it, use `Style.font.title` (14 px) for normal
  text. On master that is 16 lines: `BrowserView.qml:165` (header count),
  `:248` `:259` (list rows), `:355` `:365` `:375` `:391` `:403` `:413` `:423`
  `:438` `:451` (detail pane), `:470` (footer), and `ShortcutSheet.qml:46`
  `:54` `:60`. So the Plugin Browser's text is 1 px smaller than flatsnap's at
  the default size, 2 px at base 20, while the search field (14 px) is larger
  than the list it filters (13 px).
- **Nothing stops a multiplier coming back.** flatsnap added a
  `no-text-multiplier` flake check. This repo's `checks` (`flake.nix:118`)
  has `default` and `files`, and neither looks at font sizes.

The #16 owner decision was "option B" (two steps up, body at `subtitle`); the
recommended "option A" was body at `title`. #26 is in effect a request to
move to option A so the five nixarchy menus (flatsnap, pkg, devenv,
distrobox, plugin-browser) render text at the same sizes.

## Proposed outcome

- At every `base-size`, the panel's normal text, card title and search field
  are the same size as the same elements in nixarchy-flatsnap: normal text
  `Style.font.title`, titles `Style.font.heading`, input `Style.font.title`.
- The search field and the list it filters are the same size.
- `nix flake check` fails if a QML file sets a text size that is not a bare
  `Style.font.*` token, or reintroduces `uiScale` / `textScale` / `px(`.
- The card's size, keys and layout behave as they do after #16.

## Affected users and systems

- Everyone who opens the Plugin Browser panel (Super+Alt+U, the Add Plugin
  row, the bar button): body text grows from 13 to 14 px at base 12, so
  slightly fewer rows and characters per line fit in the same card.
- `BrowserView.qml`: the 13 `Style.font.subtitle` lines above.
- `ShortcutSheet.qml`: its 3 `subtitle` lines, and possibly its fixed column
  widths `Style.space(120)` / `Style.space(220)` (`:42`, `:50`), which #16
  sized for 13 px text.
- `flake.nix`: a new check next to `default` and `files`.
- `BarWidget.qml`: the bar button (`fontSize: Style.font.caption`, `:116`) and
  the update popup (`Style.font.body` / `caption`, `:148` `:156` `:166`) use
  tokens already. They are bar UI, not the menu, and are expected to stay as
  they are; the new check still has to accept them.
- `docs/img/01`–`09`, `tour.gif`, `tour.webm`: still show the pre-#16 1.45×
  panel (last touched in `5c9db11`, #12). #16's plan step 11 retakes them;
  doing that once, after this change, avoids a second retake.
- `CHANGELOG.md`: the #16 line (`:26`) says the panel uses the theme's font
  sizes; one line for #26.

## Constraints

- No multiplier of any kind on a font token; every size is a bare
  `Style.font.*` token.
- Must not undo #16's screen-relative card: `Menu.qml:29-34` (shares, floor,
  ceiling) and `Model.cardExtent` (`Model.js:235-238`) stay as they are.
- The flake check must not false-positive on sizing math that is not text:
  `Model.cardExtent`'s `screen * share`, `Menu.qml:29-30` `0.6` / `0.7`,
  `Math.max(1, Style.space(2))` at `Menu.qml:97`. So it matches on the text
  properties (`pixelSize:`, `fontSize:`), not on `*` or decimals in general.
- The check must actually catch `pixelSize: Style.font.title * 1.45`.
  flatsnap's regex accepts any whitespace after the token, so that line
  passes it; only the `Math.round(...)` form is caught there.
- The check must accept the token followed by `;` and more properties on the
  same line (`BarWidget.qml:148`).
- Keys, `Text.PlainText`, and the plugin's package contents are unchanged. No
  new dependencies.

## Open questions

1. **Move body text to `Style.font.title` (option A)?** Recommended: yes, all
   16 `subtitle` lines. Matching the family is the point of #26, and it lines
   the list up with the search field. Cost: 1 px per line at base 12.
2. **Is any text deliberately smaller** (the footer hint `:470`, the header
   count `:165`, the dim detail lines)? Recommended: no, all to `title`, as
   flatsnap did. Hierarchy comes from bold, colour and `dim`, not size.
3. **ShortcutSheet column widths.** Recommended: grow them with the text
   (13 → 14 px) to `Style.space(130)` and `Style.space(240)`, the same rule
   #16 used, and confirm on screen that the longest key label fits.
4. **Scope of the flake check.** Recommended: every `*.qml` in the repo, not
   only `Menu.qml` (the text lives in `BrowserView.qml` and
   `ShortcutSheet.qml` here). Named `no-text-multiplier` like flatsnap's, with
   a stricter pattern that allows only `;`, `}` or end of line after the
   token, and covers `fontSize:` too. Should the tightened regex also be sent
   back to flatsnap? Recommended: yes, a separate issue there.
5. **Screenshots.** Recommended: this change lands before the #16 retake
   (plan step 11), and the retake then covers both, once.
6. **`BarWidget.qml` popup** (`body` / `caption`). Recommended: leave it. It
   is a bar popup and matches the shell's other bar popups, not the menus.
