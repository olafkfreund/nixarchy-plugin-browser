# Spec: Run inside the Omarchy shell as a keyboard-driven panel with its own keybinding

## Design

### Facts this rests on (checked 2026-09-22)

- **`menu` plugins.** A `menu`-kind plugin is summoned on demand by
  `omarchy-shell shell toggle <id> '<json>'`. The host calls
  `open(payloadJson)`, `close()` and `toggle()` and reads `opened`.
  `nixarchy.devenv/Menu.qml` implements this with a full-screen
  `PanelWindow`:
  - layer `Overlay`, `WlrKeyboardFocus.Exclusive`;
  - a scrim, where a click outside the card closes it;
  - a `BorderSurface` card that hosts a shared view, drawn at `uiScale` 1.45.
- **State.** State lives in a `pragma Singleton` object registered in
  `qmldir` (`DevenvState`). It runs the CLI with `Process` and
  `StdioCollector`, and starts detached things with `Quickshell.execDetached`
  using fixed argv.
- **Keybindings.** They live in `~/.config/hypr/<name>-binds.lua`, one
  `o.bind(keys, description, command)` line each. On this machine they are
  Home Manager symlinks (`microvm-binds.lua`), or copied by hand. The
  user-owned `~/.config/hypr/bindings.lua` loads each one with
  `pcall(require, "hypr.<name>-binds")`.
- **The menu.** It is `$OMARCHY_PATH/default/omarchy/omarchy-menu.jsonc`,
  overridden by id from `~/.config/omarchy/extensions/omarchy-menu.jsonc`.
  **nixarchy manages that extension file:** it is regenerated from
  `programs.nixarchy.menu.extraEntries` ("reuse an existing id to override
  it"), and hand edits are overwritten on rebuild. This machine already
  declares entries there. The row to replace is `setup.plugin.add`, which
  today runs
  `omarchy-launch-floating-terminal-with-presentation 'omarchy-plugin-add'`.
- **The shell re-reads both menu files on change** (`watchChanges: true`),
  and it runs a row's `action` with `Quickshell.execDetached`.
- **No IPC from the sandbox.** This build sandbox cannot reach the shell's
  IPC (`omarchy-shell is not running`). QML behaviour can only be verified on
  the user's desktop.
- **Free keys.** Super+Alt+U is free: the taken Super+Alt keys are A, B, E,
  N, P, Q and V.

### Decisions on the intent's open questions

| Question | Decision |
|----------|----------|
| Keybinding | **Super+Alt+U**, description "Plugin browser" |
| Where the agent session runs | A floating terminal, the same `omarchy-launch-tui --app-id=TUI.float` that `update.sh` uses, running `nixarchy-plugin-fix <id> --mode explain\|fix`. That tool needs a TTY, and it already asks and confirms everything itself. |
| The gum TUI | **Kept** as the terminal fallback, and reachable from the bar button (see below). |
| Bar widget | The button **toggles the full-screen surface**, not a small popup. The update dot and update popup stay as they are. See *Alternatives* for why no popup. |
| Menu row | **Declarative:** `programs.nixarchy.menu.extraEntries."setup.plugin.add"` in the user's flake. The README gives the snippet, and this machine gets it in its own config repo (see Machine wiring). Hand-editing the extension file is not offered, because it would be overwritten. |

### Files

The layout follows `nixarchy.devenv`. Everything sits at the plugin root,
because the shell loads entry points by path.

| File | Role |
|------|------|
| `manifest.json` | `kinds: ["menu", "bar-widget"]`, `entryPoints: {menu: "Menu.qml", barWidget: "BarWidget.qml"}`, version 0.4.0 |
| `qmldir` | `singleton BrowserState 1.0 BrowserState.qml` |
| `BrowserState.qml` | A singleton. It runs `lib/catalog.sh list` and `omarchy-plugin-audit … --json`, and starts the terminal for fix/explain. It holds the catalog rows, the selected plugin's audit report, and busy/error flags. |
| `BrowserView.qml` | The keyboard view: search field, result list, detail pane and confirm bar |
| `ShortcutSheet.qml` | The `?` overlay listing every key |
| `Menu.qml` | The full-screen surface. It copies devenv's `Menu.qml` structure and hosts `BrowserView`. |
| `BarWidget.qml` | Unchanged, except that a click runs the same toggle through IPC instead of opening a terminal |
| `hypr/plugin-browser-binds.lua` | `o.bind("SUPER + ALT + U", "Plugin browser", "omarchy-shell shell toggle io.github.olafkfreund.nixarchy-plugin-browser '{}'")` |
| `lib/catalog.sh` | **New.** Catalog fetching, moved out of `bin/omarchy-plugin-audit` and `bin/omarchy-plugin-browser`, which both source it. That removes the duplicate the ponytail review found. It adds `list`, which prints one compact JSON array for the panel. |

### Data flow

1. **Catalog.** `BrowserState` runs
   `/run/current-system/sw/bin/bash <plugin>/lib/catalog.sh list` through
   `Process`. It uses the existing size-bounded, cached download (32 MiB
   ceiling, 1 h TTL, owner-only cache). `jq` then projects each community
   plugin to
   `{id, name, author, category, stars, tags, badge, description, repo, installCommand, installAvailable}`,
   sorted by stars. The shell parses that output (roughly 0.5 MB for about
   3,100 rows) once per open, not the 8 MB file. Filtering is a plain JS
   substring match over those rows, run 80 ms after the last keystroke.
   **The plan measures parse and filter times**, and moves filtering into a
   `WorkerScript` if a filter takes more than 16 ms.
2. **Audit.** `a`, or opening details, runs
   `<plugin>/bin/omarchy-plugin-audit <id> --json` in a `Process`. A spinner
   shows while it runs, which can take several seconds while it clones. The
   report fills the detail pane: security outcome, findings, capabilities,
   the NixOS verdict and its findings, and the commit posture. Exit codes 2
   and 3 show stderr's last line as an error.
3. **Agent.** `e` (explain) or `f` (fix) runs `Quickshell.execDetached` with
   `["/run/current-system/sw/bin/omarchy-launch-tui", "--app-id=TUI.float", "/run/current-system/sw/bin/bash", "<plugin>/bin/nixarchy-plugin-fix", id, "--mode", "explain"|"fix"]`.
   The warning, the confirm, the diff and the install choice all stay in that
   terminal. The panel stays open, and `a` re-audits afterwards.
4. **Install.** `i` asks "Install <name> (disabled)? y/n" in the confirm bar,
   the same pattern as devenv's `ask()`. `y` runs
   `omarchy-plugin-audit <id> --install` in a `Process` and shows the last
   lines of its output. It still installs only after a passing audit and only
   disabled; nothing is enabled. The intent said install confirmations would
   open in a terminal. An in-panel y/n is used instead, because install needs
   no interactive input: the audit runs `omarchy plugin add --yes`.
5. **Copy and open.** `c` runs `/run/current-system/sw/bin/wl-copy` with the
   catalog's `installCommand` as an argv entry, not through a shell. `o` runs
   `omarchy launch browser <repo>`, only when `repo` starts with
   `https://github.com/`, as the TUI does.

### Keys

These follow devenv's conventions. The search field has focus, so letters
type into it; single-letter actions only work in the detail pane.

| Where | Key | Action |
|-------|-----|--------|
| List | type | filter |
| List | ↑ ↓ or Ctrl+K / Ctrl+J | move |
| List | Enter | open details (and audit) |
| List | Ctrl+R | refresh the catalog, ignoring the cache |
| List | Esc | clear the search; when it is empty, close |
| Details | a | audit again |
| Details | e / f | explain / fix with the default agent (terminal) |
| Details | i | install, disabled (y/n) |
| Details | c / o | copy the install command / open the repo |
| Details | j / k | scroll the report |
| Details | Esc or ← | back to the list |
| Anywhere | ? | shortcut sheet |
| Anywhere | Super+Alt+U | toggle |

### Payload

`toggle <id> '{"id":"crmne.hyprmoncfg"}'` opens straight to that plugin's
details, and `'{"query":"monitor"}'` opens with a search already typed.
Anything else, or malformed JSON, opens the list, as devenv's `payload()`
does.

### Security in the panel

- **Plain text only.** Every `Text` that shows catalog or report data sets
  `textFormat: Text.PlainText`.
- **Validated ids.** The id is checked against `^[A-Za-z0-9][A-Za-z0-9._-]*$`
  before it goes into any argv. It is never put into a string that a shell
  parses.
- **Fixed argv.** No PATH lookups and no `sh -c`. The child `environment` is
  the same root-owned PATH that `BarWidget.qml` already uses.
- **Data only.** The panel reads the catalog projection and audit JSON, never
  a plugin's files. `JSON.parse` failures show an error and never throw into
  the shell.

### Machine wiring (this machine, with consent)

This goes in the user's config repo, not this repo, and in its own commit
there:
- `programs.nixarchy.menu.extraEntries."setup.plugin.add" = { icon = "󰖟"; label = "Add Plugin"; action = "omarchy-shell shell toggle io.github.olafkfreund.nixarchy-plugin-browser '{}'"; };`
- `home.file.".config/hypr/plugin-browser-binds.lua".source` pointing at the
  file in this repo, the same way `microvm-binds.lua` is provided.
- One `pcall(require, "hypr.plugin-browser-binds")` line in `bindings.lua`.

The README documents the same three steps for other nixarchy users, plus the
manual route: copy the `.lua` file and add the `pcall` line.

## Alternatives rejected

- **A small bar popup (`KeyboardPanel`) that also hosts the view,** as podman
  and devenv do. A search list plus a detail pane with findings does not fit
  a popup, the button already owns the update popup, and one host is half the
  code. The bar button opens the full-screen surface instead. That differs
  from the intent's "bar popup"; the view is still one click from the bar.
- **Parsing the 8 MB catalog in QML.** It would block the shell's UI thread.
  `jq` projects the data outside the shell.
- **Re-implementing the scan or the NixOS rules in QML/JS.** That would give
  two implementations that drift, and it would weaken the sandbox story. The
  panel only reads `--json`.
- **Running the agent inside the panel.** The agents are interactive
  terminal programs, and `nixarchy-plugin-fix` requires a TTY and its own
  confirmations.
- **Editing `~/.config/omarchy/extensions/omarchy-menu.jsonc` directly.**
  nixarchy regenerates it from `extraEntries`, so the edit would be lost.
- **Removing the gum TUI now.** The intent keeps the CLIs, and it is the
  fallback when the shell is down.

## Risks

- **An untestable QML runtime here.** The build sandbox cannot reach the
  shell IPC, so the QML is checked with `omarchy-plugin-validate`, careful
  review against devenv, and then **a run on the user's desktop**, which the
  plan makes an explicit gate. A QML error only disables this plugin. The
  shell stays up, as it does for any plugin load error.
- **Catalog performance on a slow machine.** This is measured in the plan,
  with `WorkerScript` as the fallback.
- **Enabling a plugin with `kinds: menu`.** The shell loads the menu entry
  point on demand, not at start, so the idle cost is the bar button only.
- **The id change (0.3.0) must be installed** before the keybinding works. The
  README install steps already cover that.
- **Replacing Add Plugin** means the old direct `omarchy-plugin-add` is no
  longer in the menu. It is still available from a terminal. Removing the
  `extraEntries` line restores it.
