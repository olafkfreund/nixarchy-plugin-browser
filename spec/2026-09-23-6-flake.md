# Spec: Package the plugin as a flake for declarative install on nixarchy

## Design

### Facts (checked 2026-09-23)

- **The consumer.** `programs.nixarchy.plugins.<name>.src` (Home Manager,
  nixarchy `modules/home.nix`) links `src` into `~/.config/omarchy/plugins/<id>`,
  where the id comes from `manifest.json`. At build time it runs:
  - `omarchy-plugin-validate`, which refuses any symlink inside the folder;
  - a `\bpacman\b|\byay\b` grep over non-comment lines of
    `*.qml/*.js/*.sh/*.bash`.

  This repo fails the grep today on 3 lines: `lib/omarchy-plugin-scan.sh:164`
  and `:228` (detector patterns) and `tests/scan-nix.sh:21` (a fixture).
- **The convention** is `olafkfreund/nixarchy-microvm`'s `flake.nix`, the
  plugin `nixos_config` already declares this way:
  - `packages.<system>.default`: a `runCommand` that copies an **explicit file
    list**. It uses plain copies because the validator refuses symlinks, so
    `symlinkJoin`/`linkFarm` fail.
  - `homeManagerModules.default`: a `programs.<name>.keybinding` option that
    writes `~/.config/hypr/<name>-binds.lua` from the plugin's own `.lua`
    file, with `null` for no bind.
  - `checks.<system>.default`: runs the tests.
  - Systems are `x86_64-linux` and `aarch64-linux`, with nixpkgs
    `nixos-unstable`.
- **Git and store awareness.** `lib/update.sh check` already reports
  `git_managed` (`[[ -d $UPD_DIR/.git ]]`), and a store install has no
  `.git`. Every tool runs as `bash <file>` and resolves its folder with
  `readlink -f "${BASH_SOURCE[0]}"`, so nothing needs an exec bit and nothing
  writes into its own folder.

### `flake.nix` (new)

```nix
{
  description = "nixarchy-plugin-browser -- browse, audit and NixOS-check Omarchy plugins, in the shell on Super+Alt+U";
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

  outputs = { self, nixpkgs }:
    let
      systems = [ "x86_64-linux" "aarch64-linux" ];
      forAll = nixpkgs.lib.genAttrs systems;
      manifest = builtins.fromJSON (builtins.readFile ./manifest.json);

      # Exactly what the plugin needs at runtime. Tests, install scripts and the
      # intent/spec/plan documents stay in the repository.
      files = [ ./manifest.json ./qmldir ./LICENSE ./README.md ./CHANGELOG.md ./Model.js
                ./BarWidget.qml ./Menu.qml ./BrowserView.qml ./BrowserState.qml ./ShortcutSheet.qml ];
      dirs = [ ./bin ./lib ./hypr ];

      pluginFor = pkgs: pkgs.runCommand "nixarchy-plugin-browser-${manifest.version}" { meta = …; } ''
        mkdir -p "$out"
        ${cp each file}; ${cp -r each dir}
      '';
      cliFor = pkgs: plugin: pkgs.runCommand "nixarchy-plugin-browser-cli-${manifest.version}" { } ''
        mkdir -p $out/bin
        for t in omarchy-plugin-audit omarchy-plugin-browser nixarchy-plugin-fix; do
          printf '#!%s\nexec %s %s "$@"\n' ${pkgs.runtimeShell} ${pkgs.bash}/bin/bash ${plugin}/bin/$t > $out/bin/$t
          chmod +x $out/bin/$t
        done
      '';
    in {
      packages = forAll (system: let pkgs = nixpkgs.legacyPackages.${system}; in rec {
        default = plugin;
        plugin = pluginFor pkgs;       # for programs.nixarchy.plugins.*.src
        cli = cliFor pkgs plugin;      # for home.packages: the three tools on PATH
      });

      homeManagerModules.default = { config, lib, ... }: …;   # keybinding, as microvm

      checks = forAll (system: { default = …; });   # see Verification
    };
}
```

Consumer (later, in `nixos_config`):

```nix
programs.nixarchy.plugins.plugin-browser.src =
  inputs.nixarchy-plugin-browser.packages.${pkgs.stdenv.hostPlatform.system}.default;
home.packages = [ inputs.nixarchy-plugin-browser.packages.${…}.cli ];   # optional
```

- **The CLI wrappers** run the scripts from inside the plugin package, so
  `SELF_DIR` is still `<plugin>/bin`, and the audit still finds
  `../lib/omarchy-plugin-scan.sh` and `../lib/catalog.sh`. The scripts keep
  their fixed root-owned `PATH`, so the tools they call come from the system
  profile, as today. The flake adds no runtime dependencies.
- **`homeManagerModules.default`** follows microvm exactly:
  `programs.nixarchy-plugin-browser.keybinding`, default `"SUPER + ALT + U"`,
  type `nullOr (strMatching "[A-Z0-9_ +]+")`. It writes
  `.config/hypr/plugin-browser-binds.lua` by substituting the chord into
  `./hypr/plugin-browser-binds.lua`. `nixos_config` currently writes that file
  itself (#1971). Moving it to this module is that repo's later change and
  stays out of this one.

### The pacman check

The detector patterns match the same text, but the literal words are gone:
`pacman` becomes `pac[m]an` and `yay` becomes `y[a]y`, in the two scanner
lines. Each gets a comment saying why: nixarchy's build check greps for the
bare words, and a detector must not read as an invocation. `tests/` is not in
the package, so the fixture never reaches the check. `tests/scan-nix.sh` is
extended to prove detection is unchanged:
- `pacman -S foo` in `run.sh` still yields `imperative-pkg`, as it already
  asserts;
- a new line, `yay -S bar`, also yields it;
- the `package-manager` CAP still fires for both.

### Updates on a store install

`BarWidget.qml` already receives `git_managed`. When it is `false`, the update
popup:
- still shows the version and the changelog notes;
- replaces the Update… button with the line *"Installed through Nix: update
  with `nix flake update nixarchy-plugin-browser` and rebuild."*;
- keeps Later.

`lib/update.sh` itself does not change; `cmd_terminal` already refuses a
non-git install.

### Docs

The README gets an "Install with Nix" section: the input, the `plugins` line,
the optional `cli` package and keybinding module, and a note that enabling
stays `omarchy plugin enable <id>`. `install.sh` stays as the non-Nix route.

## Alternatives rejected

- **`src = inputs.nixarchy-plugin-browser`, the raw flake source.** It would
  install `tests/` and the intent, spec and plan documents into the plugin
  folder, and the test fixture would fail nixarchy's pacman check. It also
  differs from the microvm convention.
- **Copying the whole tree with a filter** (`lib.fileset`) instead of an
  explicit list. It is shorter, but a new file lands in the plugin unless
  someone remembers to exclude it. The explicit list is microvm's choice, and
  it fails closed.
- **Keeping the literal words and relying on comments.** The check ignores
  only whole-line comments, and these are code.
- **Hiding the update alert on a store install.** A new version is still worth
  knowing about. Only the button is wrong.
- **A NixOS module or an overlay.** Nothing needs one; the consumer is Home
  Manager.

## Risks

- **The file list goes stale.** A new runtime file that is not added to the
  list is missing from the package. `checks.default` builds the package and
  runs `omarchy-plugin-validate` and a smoke check (`bash bin/omarchy-plugin-audit
  --help` from the package), but only the desktop check proves the QML loads.
  The README's Layout section and the list are kept side by side.
- **nixarchy's check changes.** It is used as it is, and the flake's own check
  reproduces the pacman grep, so a regression shows here first.
- **The plugin id.** `programs.nixarchy.plugins.<name>` links by the
  manifest's id, so the `<name>` key is only a label.

## Verification

- `nix flake check` passes. That covers `checks.default`:
  - `tests/scan-nix.sh`, `tests/catalog-list.sh` and `tests/model-check.mjs`;
  - `omarchy-plugin-validate` on the package;
  - nixarchy's exact pacman grep on the package, which must find nothing;
  - the CLI wrapper `--help` smoke run.
- `nix build .#plugin`: the output has no symlinks
  (`find $out -type l | wc -l` is 0) and has none of `tests`, `intent`, `spec`
  or `plan`.
- `nix build .#cli`: `result/bin/omarchy-plugin-audit crmne.hyprmoncfg --json | jq .outcome`
  gives `review-required`, run from the store copy.
- **A real consumer:** evaluate a throwaway Home Manager configuration, or
  p620's with `--override-input nixarchy-plugin-browser path:.`, using
  `programs.nixarchy.plugins.plugin-browser.src`. nixarchy's validation
  derivation must build.
- Existing checks: shellcheck adds no new warnings, and `omarchy-plugin-validate .`
  passes on the working tree.
