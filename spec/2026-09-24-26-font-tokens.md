# Spec: The panel uses the same text sizes as the other nixarchy menus

Approved decisions this spec builds on (intent approval, `f516513`):

1. All 16 `Style.font.subtitle` lines move to `Style.font.title` (option A),
   including the header count, the footer hint and the dim detail lines.
2. ShortcutSheet columns grow to `Style.space(130)` / `Style.space(240)`;
   the owner checks the fit on screen.
3. A `no-text-multiplier` flake check over every `*.qml`, on `pixelSize:` /
   `fontSize:` only, allowing only `;`, `}` or end of line after the token.
   The same hole in flatsnap is filed separately as
   olafkfreund/nixarchy-flatsnap#21.
4. This lands before #16's screenshot retake (#16 plan step 11), so the
   retake is done once.
5. `BarWidget.qml`'s popup is unchanged.

Added at spec approval (olafkfreund):

6. The ShortcutSheet overflow is fixed here, not as a follow-up: the "what"
   column wraps within the width left after the group and keys columns, so
   no row runs past the card at the minimum card width `Style.space(560)`.
   Proven by computation; the owner's on-screen check stays manual.

Token sizes at the default base size 12 (from #16's spec): `subtitle` 13,
`title` 14, `heading` 16. `Style.space(n)` is `n * baseFontSize / 12`, so a
column width in `space()` units grows with the text at every base size.

## Design

### 1. Body text to `Style.font.title` (`BrowserView.qml`, `ShortcutSheet.qml`)

Replace `font.pixelSize: Style.font.subtitle` with
`font.pixelSize: Style.font.title` on exactly these lines, nothing else on
them:

- `BrowserView.qml`: `:165` (header count), `:248` `:259` (list rows),
  `:355` `:365` `:375` `:391` `:403` `:413` `:423` `:438` `:451` (detail
  pane), `:470` (footer). 13 lines.
- `ShortcutSheet.qml`: `:46` `:54` `:60`. 3 lines.

After it, `grep -c 'Style.font.subtitle'` is 0 in both files, and the panel
uses three tokens: `heading` (card title `BrowserView.qml:153`, detail name
`:343`, sheet title `ShortcutSheet.qml:29`), `title` (everything else,
including the search field `:187`). Hierarchy stays with bold, colour and
`dim` opacity, as in flatsnap. Colours, weights, `Text.PlainText`, elide and
layout properties are untouched.

### 2. ShortcutSheet column widths (`ShortcutSheet.qml:42`, `:50`)

`width: Style.space(120)` → `Style.space(130)` (group column),
`width: Style.space(220)` → `Style.space(240)` (keys column). The third
column (`what`) gets a width and wraps (decision 6, below).

Fit, computed rather than looked at. The shell font on this machine resolves
to FiraCode Nerd Font (`fc-match monospace`), advance 0.6 em, so 8.4 px per
character at 14 px, base 12:

| Column | Longest label | Chars | Width at 14 px | Column |
| ------ | ------------- | ----: | -------------: | -----: |
| group  | `Anywhere`    | 8     | 67 px          | 130 px |
| keys   | `↑ ↓  Ctrl+K Ctrl+J` | 18 | 151 px     | 240 px |
| keys   | `Esc  ←  Backspace`  | 17 | 143 px     | 240 px |

Both text (`title` = `base * 1.167`) and width (`space()` = `n * base / 12`)
scale linearly with base size, so the ratio holds at every `base-size`. The
margin (~60 px on the keys column) also covers a proportional theme font and
the arrow glyphs falling back to another font. The owner's on-screen check
stays in Verification as the final word.

### 2a. The "what" column wraps (`ShortcutSheet.qml:56-61`, decision 6)

Today the third `Text` has no width, so a long row runs past the card on a
narrow card (see the fit below). It gets a width equal to what is left of the
sheet's content column after the other two columns and the two row gaps, and
wraps inside it:

```qml
Column {
  id: rows                       // new id on the existing Column (:20)
  ...
      Text {
        width: rows.width - Style.space(130) - Style.space(240) - 2 * Style.spacing.lg
        text: modelData.what
        color: root.foreground
        font.family: root.fontFamily
        font.pixelSize: Style.font.title
        wrapMode: Text.Wrap
        textFormat: Text.PlainText
      }
```

- `rows.width` is the sheet width minus the Column's `Style.spacing.lg`
  margins; `2 * Style.spacing.lg` is the Row's `spacing` between its three
  children. The Repeater parents each delegate `Row` to `rows`, so the id is
  in scope.
- `Text.Wrap` breaks at word boundaries and only inside a word that is wider
  than the column. The longest word in `Model.SHORTCUTS[*].what` is 10
  characters (`repository`, `(terminal)`), 84 px, so at the widths below no
  word is split.
- `Text.PlainText`: the sheet's `Text`s have no `textFormat` today (AutoText).
  The strings are constants in `Model.js`, not plugin data, but the wrapped
  one is given `Text.PlainText` so it follows the rule in
  `BrowserView.qml:11`. The group and keys `Text`s are not changed.
- The group and keys columns keep fixed widths and do not wrap: their
  longest labels fit with a margin (table above).
- A `Row` takes the height of its tallest child, so a wrapped row pushes the
  rows below it down; the `topPadding` group gap (`:39`) is unchanged.

Fit at the minimum card width, base 12 (all figures scale by `base / 12`, so
the character count per line is the same at every base size when the card
is at its floor):

| Quantity | Value |
| -------- | ----: |
| Card width (`Style.space(560)`) | 560 px |
| Frame (card minus `popupPadding` 14 + border 2, each side) | ~528 px |
| `rows.width` (minus 2 × `spacing.lg` 8) | ~512 px |
| "what" width (512 − 130 − 240 − 2 × 8) | ~126 px, 15 characters at 8.4 px |
| Widest row today, `f` / `fix a copy with your default agent (terminal)` | 45 chars, 378 px: ends ~252 px past the card's right edge |
| Same row wrapped | 4 lines (`fix a copy with` / `your default` / `agent` / `(terminal)`), each ≤ 126 px |

So after the change every row ends at or before `rows.width`; no row runs
past the card at `Style.space(560)`. At the ceiling width
`Style.space(960)` the column is ~526 px (62 characters) and no row wraps.
The vertical consequence at small cards is in Risks.

### 3. `no-text-multiplier` check (`tests/no-text-multiplier.sh`, `flake.nix`)

One script, so the same scan runs in the flake, in `tests/run.sh`, and
against a mutated copy for the RED proof:

```bash
#!/usr/bin/env bash
# tier: hermetic
#
# tests/no-text-multiplier.sh [dir] — every text size in a QML file is a bare
# Style.font.* token (#26): no factor, no uiScale/textScale/px() helper.
# Prints "ok" and exits 0, or the offending lines and exits 1.
set -uo pipefail
ROOT=${1:-"$(cd -- "$(dirname -- "$0")/.." && pwd)"}
# Hidden dirs below ROOT (.git, .claude/worktrees) are skipped; ROOT itself
# may sit under one.
mapfile -d '' qml < <(find "$ROOT" -mindepth 1 -name '.*' -prune -o -name '*.qml' -print0)
[ ${#qml[@]} -gt 0 ] || { echo "no qml under $ROOT"; exit 1; }
# Each pixelSize:/fontSize: binding, cut at ; or } so BarWidget.qml:148's
# "...: Style.font.body; font.bold: true" is judged on its first binding.
bad=$(grep -noHE '(pixelSize|fontSize):[^;}]*' "${qml[@]}" |
  grep -vE ':(pixelSize|fontSize):[[:space:]]*Style\.font\.[A-Za-z]+[[:space:]]*$')
words=$(grep -nHE '\b(textScale|uiScale)\b|\bpx\(' "${qml[@]}")
[ -z "$bad$words" ] || { printf '%s\n' "$bad" "$words" | sed '/^$/d'; exit 1; }
echo ok
```

- Scope: every `*.qml` under the root (today `BarWidget`, `BrowserState`,
  `BrowserView`, `Menu`, `ShortcutSheet`). Only `pixelSize:` / `fontSize:`
  bindings are judged, so `Model.cardExtent`'s `screen * share`,
  `Menu.qml:29-30` `0.6` / `0.7`, `Math.max(1, Style.space(2))` and every
  other `Style.space()` expression are never looked at. `Model.js` sets no
  text sizes and is not scanned.
- `grep -o` with `[^;}]*` judges each binding on its own, so a second
  `pixelSize:` later on the same line is checked too, and `; font.bold` after
  a good token passes. The tail must be whitespace only: `* 1.45`,
  `+ 2`, `Math.round(...)`, a trailing `// comment`, and a non-`Style.font`
  value all fail.
- `uiScale`, `textScale` and `px(` are refused anywhere in a `.qml`, as
  whole words, as the intent's outcome says.
- No `.qml` found fails, so a moved tree cannot pass vacuously. Hidden
  directories under the root are pruned, so a local run in the main checkout
  does not scan other branches' `.claude/worktrees/*`; the prune is by name
  below the root, so a root that itself sits under `.claude/` still works.

`flake.nix` `checks` gets a fourth attribute next to #19's `default`, `files`
and `hm-module`:

```nix
# Text sizes are bare Style.font.* tokens; no multiplier comes back (#26).
no-text-multiplier =
  pkgs.runCommand "nixarchy-plugin-browser-no-text-multiplier"
    { nativeBuildInputs = with pkgs; [ gnugrep findutils gnused ]; }
    ''
      bash ${./tests/no-text-multiplier.sh} ${self}
      touch $out
    '';
```

It scans `${self}` (the repository), not the package, so a QML file left out
of `files` is still checked. Being `# tier: hermetic`, the script also runs
inside `default` (against the packaged copy) and in `tests/run.sh`; that
second run costs a few milliseconds and needs no special case.

The script above was run as written while drafting this spec: `ok` on the
current tree, and exit 1 listing all five lines on a copy with `* 1.45`,
`Math.round(... * 1.45)`, a second `font.pixelSize: 20` on
`BarWidget.qml:148`, `uiScale` and `px(12)`.

## Alternatives rejected

- **Keep body at `subtitle` (option B, #16's choice).** The owner chose A;
  B leaves the list 1 px smaller than the search field and than flatsnap.
- **Keep the footer, header count or dim lines at `subtitle`.** Rejected in
  the intent approval; size-based hierarchy is what the family avoids.
- **Copy flatsnap's regex.** It accepts anything after whitespace following
  the token, so `Style.font.title * 1.45` passes it; only the
  `Math.round(...)` form is caught. Filed back as olafkfreund/nixarchy-flatsnap#21.
- **Flag any `*` or decimal in QML.** False positives on `cardExtent`, the
  card shares and `Style.space()` math, as the intent's constraints say.
- **Check inline in `flake.nix` only.** The RED proof would then need a
  mutated git tree and a `nix build`; a script with a directory argument
  proves it with one `bash` call and is the same code the flake runs.
- **Also scan `pointSize:`, `font:` object bindings.** Not used anywhere in
  the repo and out of the approved scope; add it the day one appears.
- **Leave the sheet's width overflow as a follow-up issue.** The draft
  spec did this; the approver chose to fix it here (decision 6).
- **Shrink or wrap the keys column instead.** The keys labels are what the
  sheet is for; wrapping `Esc  ←  Backspace` mid-chord reads worse than
  wrapping the prose description.
- **Measure label widths in a live panel.** No live desktop actions by
  agents; the widths are computed above and the look is the owner's check.

## Risks

- **Less fits in the card.** Every body line is 1/13 (~8%) taller and wider
  at every base size: fewer list rows, detail lines wrap sooner. The card
  size (#16) is unchanged. Visible on small laptop screens at large
  `base-size`; the owner's on-screen check covers it.
- **ShortcutSheet height on a small card.** Wrapping trades the horizontal
  overflow for height. At the card's floor (`Style.space(560)` ×
  `Style.space(420)`, reached when the screen is under about 933 × 600
  logical px at base 12, or a 1366 × 768 laptop at base 16) the 16 rows
  become about 40 lines, about 785 px at base 12, against a frame about
  388 px tall. The sheet has no scroll and `frame` clips (`Menu.qml`,
  `clip: true`), so the bottom rows (the `Anywhere` group, including how to
  close the sheet) are cut off there. Today the same card shows all 16 rows
  (about 352 px) with the long ones running off the right edge. Computed for
  common screens: base 12 fits at 1280 × 720 and up; base 16 clips at
  1366 × 768 and fits at 1920 × 1080; base 20 clips at 1920 × 1080 and fits
  at 2560 × 1440. The approved decision is about width and is implemented as
  decided; if the owner's on-screen check finds the clipped height worse than
  the old overflow, the follow-up is a scrolling sheet or a narrower keys
  column, filed separately. Esc, `?` and `q` still close the sheet when its
  last rows are hidden.
- **Check blind spots.** A binding split over two lines
  (`pixelSize: Style.font.title` then `* 1.45` on the next line) passes,
  because grep is line-based. Nothing in the repo is written that way; the
  code style puts a binding on one line. A size set through a JS helper in
  `Model.js` is not scanned. Both are accepted, not fixed.
- **Check false positive.** A legitimate trailing comment after a size
  token fails the check. Deliberate: put the comment on the line above.
- **Screenshot ordering.** If #16's retake runs before this merges, the
  images show 13 px body text and need a second retake.
