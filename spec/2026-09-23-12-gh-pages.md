# Spec: a GitHub Pages site in nixarchy's style, with screenshots and a recording

## Decisions on the intent's open questions

The intent was approved with its three questions open. This spec takes one
answer each; approving the spec approves these.

1. **nixarchy gets the media in a follow-up PR, after #915 merges.** #915's
   plan is approved and its CI is green; adding images widens it for no gain.
   The follow-up is small: images plus the manual section's figure lines
   and a link to the site.
2. **The captures use razer's current theme,** named in the caption as
   nixarchy's captions do ("Recorded on razer, in <theme>"). No theme is
   switched for the recording, so nothing on the owner's desktop changes.
3. **Pages is enabled on this repo, with GitHub Actions as its source,** once
   the site PR is merged: `gh api -X POST repos/olafkfreund/nixarchy-plugin-browser/pages -f build_type=workflow`.
   The site is public, as the repository already is.

## Design

### Files: a fork of nixarchy's site, as nixarchy-pkg did it

nixarchy-pkg's `docs/` is the template, because it already solved "nixarchy's
design, for a plugin". Its files are copied from **nixarchy's** originals
(not from pkg's), with the same honesty header pkg uses:

| File | From | Change |
|---|---|---|
| `docs/assets/style.css` | nixarchy `docs/assets/style.css` | fork header; only the `.logo` font-size clamp is retuned for the wordmark width, marked `CHANGED FROM NIXARCHY'S COPY` |
| `docs/assets/manual.js` | nixarchy | byte-identical |
| `docs/_layouts/manual.html` | nixarchy | site title and links only |
| `docs/_layouts/home.html` | nixarchy-pkg (nixarchy's home is its `index.md` on `manual`) | titles and links |
| `docs/_includes/logo.html` | new, pkg's pattern | a figlet wordmark in `delta_corps_priest_1`, nixarchy's typeface, with `role="img"` and an `aria-label` |
| `docs/_config.yml` | pkg's shape | `title: nixarchy.plugin-browser`, `baseurl: /nixarchy-plugin-browser`, and the `nav` below |
| `docs/index.md` | new | the landing page |
| `docs/llms.txt` | pkg's shape | every page, for agents |

**The wordmark** is `PLUGINS` if figlet renders it at most 92 columns wide
(nixarchy's own width), otherwise `PB`. The tagline carries the full name,
as pkg's does.

### Pages

The landing page, `docs/index.md`, has:
- a one-paragraph pitch;
- the tour recording with its poster;
- three stills;
- "on nixarchy it's already there; elsewhere, install it" links.

The manual (`docs/manual/`, with the sidebar in this order):

| Page | Content |
|---|---|
| `index` | what this is, and a table linking every page |
| `getting-started` | on nixarchy (a default plugin; the off switch); by hand (install.sh, flake, `omarchy plugin add`) |
| `the-panel` | search, the list, details, every key (the `?` sheet), the payloads `{"id"}` / `{"query"}` |
| `the-audit` | the sandbox, the security verdict, the NixOS verdict and its rules, exit codes and `--json` |
| `the-agent` | `e` / `f`, what the agent gets and doesn't, the confirms, the residual prompt-injection risk, patches |
| `installing` | `i`: disabled, pinned to the audited commit; the URL row on nixarchy |
| `previews-and-privacy` | what is fetched, from where, when; the checks on previews; `"previews": false` |
| `from-a-terminal` | the TUI (right-click the bar button), `omarchy-plugin-audit`, `nixarchy-plugin-fix` |
| `troubleshooting` | "audit fails: no bwrap"; the re-login after a menu change; singletons need a shell restart after `omarchy plugin update` |

The content comes from the README and the three intent/spec/plan sets
already in `intent/`, `spec/` and `plan/`, which are rewritten for readers
rather than linked.

### Media

Captured on razer under ai-mirror control (the owner grants it), with
`gpu-screen-recorder` running, and announced on the bus.

- **Stills:** `docs/img/NN-name.webp`, cropped to the panel card, with no
  bar, tray or notifications in frame. The names:
  - `01-list`, `02-search`, `03-details-preview`;
  - `04-verdicts-review` (hyprmoncfg), `05-verdicts-pass` (Display Watcher);
  - `06-auditing`, `07-install-confirm`, `08-keys`;
  - `09-agent-warning` (the `e` terminal, answered No);
  - `10-add-plugin-row` (the menu, navigated by keys; **no menu search**, whose
    Files section shows document paths).
- **Tour:** `docs/img/tour.webm` (the source) and `tour.gif`. The GIF is
  cropped to the panel region, at 12 fps and 960 px wide, with a
  palette-optimised ffmpeg pass, under 4 MB. Plus `tour-poster.webp`. The
  tour runs:
  1. Add Plugin;
  2. type "monitor";
  3. open hyprmoncfg (the preview, then the verdicts scrolling);
  4. Esc;
  5. open Display Watcher (it passes);
  6. `i`, then `n`;
  7. Esc Esc.
- **Excluded:** `o` (a browser window shows a profile and bookmarks),
  `c` (the clipboard), a real `y` install, and any menu search.
- Tools: ImageMagick for WebP and crops, and ffmpeg for the GIF, both via
  `nix run nixpkgs#…`. Nothing is added to the flake.

### Publishing

`.github/workflows/pages.yml` is pkg's workflow, with two differences:
- the deploy condition names `refs/heads/master`, this repo's branch;
- it keeps both of pkg's checks: every manual page is reachable (sidebar,
  llms.txt and index), and every referenced image exists.

It runs on PRs touching `docs/**` (the checks and the build) and deploys on
push to master.

### The README and the flake

- **The README** gains the site link and the tour GIF at the top.
- **The flake:** `docs/` is not in the `plugin` package's explicit file
  list, so the package is byte-for-byte unchanged. `checks.default`
  already fails on a repo-only file in the package, and that proves it.

### nixarchy, in a follow-up PR after #915 merges

- **Images:** `docs/img/plugins/plugin-browser-{list,details,verdicts}.webp`

- **`docs/manual/plugins.md`, the Plugin Browser section:**

## Alternatives rejected

- **Link to nixarchy's stylesheet instead of copying it.** Pages cannot
  import across repositories without a build step. pkg records the same
  finding and forks it on purpose.
- **A Jekyll theme gem, or a static-site generator.** Neither looks like
  nixarchy, and both are more to maintain. nixarchy's site has no framework
  by design.
- **Capture in a VM or a nested compositor.** It doesn't show the real bar
  and theme, and nixarchy's own media are from real desktops.
- **Put the media in #915.** See decision 1.
- **Screenshots of the whole screen.** The bar shows tray state and
  notifications, which change and can be private. The panel card is the
  subject.

## Risks

- **Private data in a capture.** Mitigations:
  - crop to the card;
  - no menu search, no `o`, no `c`;
  - frame-by-frame review of the GIF before commit.
- **The design drifts from nixarchy's.** The fork header says so, and the
  one changed value is marked. A later sync is a diff against nixarchy's
  file.
- **Pages misconfigured** (legacy vs workflow): the enable call names
  `build_type=workflow`, and the first deploy's URL is checked.
- **The razer session** is shared with the step-8 test of nixarchy #915;
  both are in one recorded grant, with one announcement.

- A local build shows every page rendered with the nixarchy look:
  `nix run nixpkgs#jekyll -- build -s docs -d /tmp/site` (or the Pages
  action's output), with the sidebar order and the logo checked in a
  browser screenshot.
- `nix flake check` passes, and the plugin package is unchanged
  (`nix path-info .#plugin` before and after).
- Every image is under its budget: the GIF < 4 MB, each still < 200 KB. A
  review of each frame for private data is written down in the PR.
- After the merge and enable: https://olafkfreund.github.io/nixarchy-plugin-browser/
  answers 200 and shows the tour.
- nixarchy follow-up: its PR CI is green, and the manual section renders
  the figures.
