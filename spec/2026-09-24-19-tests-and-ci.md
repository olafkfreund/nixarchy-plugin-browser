# Spec: Run the tests on every pull request, and test the audit's gates

## Design

### Decisions carried from the approved intent

- GitHub-hosted runners only. No pull request code runs on p620.
- `x86_64-linux` only. `aarch64-linux` stays declared in the flake and is
  not built by CI.
- Dependabot for GitHub Actions only, weekly.
- `tests/catalog-list.sh` runs as a CI step outside Nix. `lib/catalog.sh`
  keeps its pinned `PATH`.
- `check` becomes a required status on `master` once it has been green on a
  few pull requests.

### Fact that changes the intent's picture (checked 2026-09-24)

The intent says `tests/preview.sh` "already runs hermetically". It does
not. I ran it in a mount namespace with `/run` and `/etc/profiles` hidden
and the tools on the caller's `PATH`:

```
FAIL: off switch: expected exit 4, got 3 (lib/catalog.sh: line 119: mkdir: command not found)
```

The test runs `bash lib/catalog.sh preview …` directly. That path exports
the pinned `PATH` (`lib/catalog.sh:134`), and no tool is left on it.
`catalog-list.sh` fails the same way. So does anything that runs
`bin/omarchy-plugin-audit` (`:51`) or `lib/update.sh` (`:25`). It passes on
a developer's machine only because NixOS has `/run/current-system/sw`.
`preview.sh` therefore goes in the host tier (below), next to
`catalog-list.sh`, and not in the flake check. The alternative is to make
`PATH` overridable. The approver already turned that down for
`catalog-list.sh`, and the same reasoning applies here.

### Two tiers, one harness

Every test is a standalone file that prints `ok` and exits 0, or names the
first failure and exits non-zero. The existing four already work this way.
Each file declares its tier in a header comment:

```
# tier: hermetic      (or: // tier: hermetic  in .mjs)
# tier: host
```

- **hermetic**: needs only the tools on the caller's `PATH` and the
  repository. It runs inside `nix flake check`.
- **host**: runs a script that pins `PATH` to `/run/current-system/sw`. It
  runs on a NixOS machine, or on the CI runner after the shim step below.

`tests/run.sh [hermetic|host|all]` (default `all`) is about 15 lines of plain
bash. It finds each `tests/*.sh` and `tests/*.mjs` whose tier line matches,
runs it with `bash` or `node`, prints `PASS <name>` or `FAIL <name>` plus the
test's output, and exits 1 if any test failed. It runs them all and does not
stop at the first failure. A file with no tier line fails the run, so a new
test cannot be skipped by accident.

**The contract for #15, #17 and #18:** add one file to `tests/` with a tier
line. Nothing else is needed: no edit to `flake.nix`, the harness or the
workflow. The fixture rules are the same as for the tests below: `mktemp -d`
plus `trap` cleanup, `CATALOG=` set to a fresh fixture, local directories or
`file://` repositories as targets, and no network.

Tier assignment:

| File | Tier | Status |
| --- | --- | --- |
| `tests/scan-nix.sh` | hermetic | existing, tier line added |
| `tests/model-check.mjs` | hermetic | existing, tier line added |
| `tests/preview.sh` | host | existing, tier line added |
| `tests/catalog-list.sh` | host | existing, tier line added |

### `flake.nix` checks

`checks.<system>.default` keeps the package assertions and the pacman/yay
grep exactly as they are. Its two explicit test lines become
`bash work/tests/run.sh hermetic`. Two new named checks sit beside it, so a
failure names what broke:

- **`checks.<system>.files`**: every runtime file in the repository is in
  the package. For each top-level `*.qml` and `*.js`, plus `qmldir` and
  `manifest.json`, in `self` (the git-tracked tree), the file must exist in
  `${plugin}`. For `bin/`, `lib/` and `hypr/`, `diff -r` against the
  package. A missing file prints its name. The reverse direction needs no
  check: a listed file that does not exist already fails evaluation.
- **`checks.<system>.hm-module`**: evaluates `homeManagerModules.default`
  with `lib.evalModules` against a stub that declares only
  `home.file.<name>.text`. It adds no home-manager input. It asserts four
  things at evaluation time:
  1. the default writes `.config/hypr/plugin-browser-binds.lua` containing
     `SUPER + ALT + U`;
  2. `keybinding = "SUPER + SHIFT + P"` replaces the chord;
  3. `keybinding = null` writes no file;
  4. a value with a quote (`"U\"); os.execute(\""`) fails the `strMatching`
     type (`builtins.tryEval` of the forced value is `false`).

  The result is a `writeText` with the evaluation results in it.

### `tests/audit-gates.sh` (host): the audit's existing refusals

It uses only the existing knobs: `CATALOG`, `AUDIT_STAGE_*`, `OMARCHY_BIN`,
`--no-sandbox`, `--export-tree`, `--json`, a local directory target and a
`file://` target. Nothing is added to `bin/omarchy-plugin-audit`.

| Gate | Fixture | Expected |
| --- | --- | --- |
| FIND → 20 | a local plugin with `eval(x)` in a QML file | exit 20, `outcome == "needs-fixes"` |
| VALIDATE fail → 20 | a clean plugin, `--no-sandbox`, `OMARCHY_BIN=<fixture dir>` holding an `omarchy-plugin-validate` that exits 1 | exit 20, `manifestValidate == "fail"` |
| clean → 0 | a clean plugin, the same with a validator that exits 0 | exit 0 |
| file limit | `AUDIT_STAGE_MAX_FILES=2`, a local plugin with 3 files | exit 3, message names the file count |
| byte limit | `AUDIT_STAGE_MAX_BYTES=10`, the same plugin | exit 3, message names the size |
| deadline | `AUDIT_STAGE_DEADLINE_SEC=0`, a `file://` git repository | exit 3, "deadline" in the message |
| symlink export | a local plugin with a symlink, `--export-tree <new dir>` | exit 20, and `<new dir>` does not exist afterwards |

The FIND and clean cases run with the sandbox (bwrap), because that is the
real path. The VALIDATE case needs `--no-sandbox`, since the sandbox fixes
`OMARCHY_BIN` to `/run/current-system/sw/bin`. Each case asserts the exit
code and one field or message. If the plan finds that a gate does not work
as shown (for example, the local path follows the symlink before
`--export-tree` sees it), that test is not written here. The bug goes to #15,
and #15 writes it as a regression test.

### `tests/update.sh` (host): `lib/update.sh`'s decisions

It sets `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` to a temporary directory and
seeds `update-check.json` with a fresh `checked`, so `fetch` is never
reached. It checks:

- `check` reports `available: true` when the cached `latest` is newer than
  the installed version. It reports `false` when they are equal, and `false`
  when the cached `latest` is older.
- `ver_gt` orders `0.10.0` above `0.9.0`.
- `dismiss 1.2.3` stores `dismissed == "1.2.3"`.
- `"update_check": false` gives `enabled: false`, and the cache is not
  touched.

`run` and `terminal` launch a terminal and are left out.

### `.github/workflows/ci.yml`

```yaml
name: ci
on:
  pull_request:
  push: { branches: [master] }
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
jobs:
  check:                      # the required status name
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { persist-credentials: false }
      - uses: cachix/install-nix-action@13d8dd58da0234aa297dedd986986ccb8e7f3e24 # v31.11.1
      - name: nix flake check (hermetic tier, package, file list, HM module)
        run: nix flake check -L
      - name: Root-owned /run/current-system/sw from the locked nixpkgs
        run: |
          sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0   # bwrap
          sudo mkdir -p /run/current-system/sw/bin
          for p in $(nix build --no-link --print-out-paths --inputs-from . \
                nixpkgs#bash nixpkgs#coreutils nixpkgs#findutils nixpkgs#gnugrep \
                nixpkgs#gnused nixpkgs#gawk nixpkgs#jq nixpkgs#file nixpkgs#git \
                nixpkgs#curl nixpkgs#bubblewrap nixpkgs#util-linux nixpkgs#diffutils); do
            sudo ln -sf -t /run/current-system/sw/bin "$p"/bin/*
          done
      - name: Host tier
        run: bash tests/run.sh host
```

- It uses `pull_request`, never `pull_request_target`. A fork's pull request
  gets a read-only token and no secrets. The workflow has no secrets.
- It has no path filters. A required check that a path filter skips stays
  "pending" forever and blocks docs-only pull requests.
- The shim is only ever built on the CI runner, and only from the flake's
  locked nixpkgs (`--inputs-from .`). The scripts under test still see a
  root-owned directory at the path they pin. None of them changes. The
  exact tool list gets confirmed in the plan by running the host tier.
- No binary cache. The intent left this open, and the approval did not
  settle it. The closure is `runCommand`s plus nodejs, jq and file from
  cache.nixos.org, so a cold run should take a few minutes. Add
  `DeterminateSystems/magic-nix-cache-action` (or Cachix) only if runs get
  slow.
- `nix flake check` only builds checks for the runner's system. That is
  `x86_64-linux`, as decided.

### `.github/dependabot.yml`

```yaml
version: 2
updates:
  - package-ecosystem: github-actions
    directory: /
    schedule: { interval: weekly }
```

Dependabot updates both the SHA and the `# vX.Y.Z` comment.

### `.github/workflows/pages.yml` hardening

- **Pinned by SHA, staying on the current major versions** so the site
  builds exactly as before. Dependabot proposes each major bump as its own
  pull request.
  - `actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0`
    (both jobs)
  - `actions/configure-pages@983d7736d9b0ae728b81ab479565c72886d7745b # v5.0.0`
  - `actions/jekyll-build-pages@44a6e6beabd48582f863aeeb6cb2151cc1716697 # v1.0.13`
  - `actions/upload-pages-artifact@56afc609e74202658d3ffba0e8f6dda462b719fa # v3.0.1`
  - `actions/deploy-pages@d6db90164ac5ed86f2b6aed7e0febac5b3c0c03e # v4.0.5`
- **`persist-credentials: false`** on both checkouts. Neither job pushes.
- **Concurrency**: `group: pages-${{ github.ref }}`, with
  `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`. A pull
  request now has its own group, and a newer push cancels its older run.
  `master` has its own group, where nothing is cancelled. A pull request can
  no longer queue behind a deploy, or a deploy behind a pull request.

All SHAs were read with `gh api repos/<owner>/<repo>/git/ref/tags/<tag>` on
2026-09-24. Each is a lightweight tag that points directly at a commit.

### Ownership

- **#19 (this issue):** `ci.yml`, `dependabot.yml`, the `pages.yml`
  hardening, `tests/run.sh`, the tier lines, the `files` and `hm-module`
  checks, `tests/audit-gates.sh` and `tests/update.sh`. All of these test
  behaviour that already exists.
- **#15:** the spoofed-VALIDATE test (a plugin whose files print a
  `VALIDATE\tok` line) and any symlink or local `--install` case beyond the
  existing `--export-tree` refusal.
- **#18:** the hostile or malformed catalog-row tests (`CATALOG=` fixture
  with bad rows, and `--category` bounds).
- **#17:** panel regressions. These go in `tests/model-check.mjs` or a new
  hermetic `.mjs`.

Each of those is one new file in `tests/` with a tier line, as described
above.

## Alternatives rejected

- **Make `lib/catalog.sh`'s pinned `PATH` overridable, so the host tests run
  inside `nix flake check`.** The approver chose a CI step instead. An
  override variable would also be a test-only bypass of the property the
  pin exists for.
- **Fake `/run/current-system/sw` inside the Nix sandbox** (a nested
  `unshare -rm` with a tmpfs over `/run`). This depends on nested user
  namespaces in the builder, which vary between hosts. It is clever in a way
  that breaks at 3am.
- **Self-hosted runner on p620.** Decided against: it would run pull request
  code on a home machine.
- **A home-manager flake input for the module check.** It is a large new
  input, used only to evaluate a module that sets one option. A two-option
  stub proves the same thing.
- **A test framework (bats, shellspec).** Ruled out by the intent. The
  existing `ok`/`FAIL` convention plus a tier line is enough.
- **A registry file listing the tests, instead of tier lines.** Every new
  test would then need two edits, and the list could drift.
- **Path filters on `ci.yml`.** They are incompatible with a required check.
- **Moving `pages.yml` to the latest majors (checkout v7, deploy-pages v5,
  and so on) now.** That changes how the site builds. The intent says it
  must not change. Dependabot proposes those bumps separately.
- **A separate job per tier.** That means two Nix installs and two status
  names to require, for no isolation gain.

## Risks

- **bwrap on the hosted runner.** Ubuntu 24.04 restricts unprivileged user
  namespaces through AppArmor. The `sysctl` line lifts that on the runner.
  If GitHub changes the image and bwrap still fails, the FIND and clean
  cases fail loudly with exit 3, "sandboxed scan failed". They do not skip.
  The fallback is the audit's own `--no-sandbox` for those two cases, and
  that would be a decision for the approver.
- **Host tests on a developer's NixOS machine see the real system.** For
  example, the real `omarchy-plugin-validate` is present there, and absent
  in CI. That is why every audit case that depends on VALIDATE sets
  `OMARCHY_BIN` itself.
- **The shim uses symlinks into `/nix/store`**, where a real NixOS system
  has a `buildEnv`. The audit's `--ro-bind /run/current-system/sw` follows
  them, and `/nix/store` is bound too, so the sandbox sees the same tools.
  If it does not, the FIND case shows it.
- **Network during host tests.** The runner is online. Each test seeds a
  fresh `CATALOG` or update cache, so no fetch path is taken. A test that
  reaches the network by mistake would still pass on a good day, and flake
  on a bad one. The plan's review step greps the new tests for any target
  that is not local.
- **Flake-check time.** Adds one module evaluation and one `diff -r`, about
  seconds.
- **The required check before it is required.** Until branch protection is
  set, a red `check` does not block a merge. That window is deliberate, per
  the approval.
- **Pages concurrency change.** Two quick pushes to `master` still run in
  order, in the same group with nothing cancelled. The only change is that
  pull requests leave that group.

## Verification

- `nix flake check -L` passes locally and in CI. Breaking each new check
  once turns it red:
  - remove `./Menu.qml` from `files`: `files` fails and names it;
  - change the default chord in the module: `hm-module` fails;
  - add `exit 1` to a hermetic test: `default` fails and names the test.
- `bash tests/run.sh host` passes on a NixOS machine and in CI. Each gate in
  `audit-gates.sh`, and each assertion in `tests/update.sh`, has been seen
  to fail once when the behaviour it tests is broken: bumping the limit,
  forcing `OC_EXIT=0`, removing the `--export-tree` symlink `die`,
  inverting `ver_gt`. This is done in a throwaway local change and never
  committed.
- A test file with no tier line makes `tests/run.sh` exit 1.
- A draft pull request shows the `check` status. Pushing a red commit to it
  turns the status red. A second push cancels the first run.
- `pages.yml`: a pull request touching `docs/` builds, but does not deploy,
  and the next merge to `master` deploys as before. `grep -n 'uses:'
  .github/workflows/*.yml` shows only 40-character SHAs, each with a
  version comment.
- Dependabot opens (or lists as up to date) the GitHub Actions updates
  within a week.
- After a few green pull requests: `gh api
  repos/olafkfreund/nixarchy-plugin-browser/branches/master/protection`
  lists `check` as a required status.
