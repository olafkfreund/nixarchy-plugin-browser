# Spec: Show the marketplace preview image in the panel

## Design

### Facts (checked 2026-09-23)

- **The catalog.** Each preview is a site-relative path in the catalog, for
  example `previewThumbnail: "assets/img/plugins/5-crmne-omarchy-hyprmoncfg-card.webp"`
  (720×405). 3379 of 3969 plugins have one.
- **The files.** `https://plugins.omarchy.org/<path>` answers `200` with
  `image/webp`; hyprmoncfg's thumbnail is 21 KB.
- **Decoding.** Quickshell's closure has `qtimageformats` (`libqwebp.so`), so a
  QML `Image` can decode WebP. `Image.sourceSize` makes Qt decode at a bounded
  size (`QImageReader::setScaledSize`), which caps decode memory whatever the
  file's header claims.
- **What exists to build on.** `lib/catalog.sh` already has the bounded, atomic,
  owner-only download pattern (`download_catalog`). The plugin's config file
  `~/.config/nixarchy-plugin-browser/config.json` already exists, for
  `update_check`.

### `lib/catalog.sh`

`list` gains one field per row: `preview: (.previewThumbnail // "")`.

It also gains a new subcommand, `catalog.sh preview <relpath>`. It prints the
absolute path of a verified local file on stdout and exits 0, or exits
non-zero with a one-line reason on stderr. In order:

1. **Off switch.** If `config.json` has `"previews": false`, exit 4 with
   "previews are off". Nothing touches the network.
2. **Path check.** `<relpath>` must match
   `^assets/img/plugins/[A-Za-z0-9][A-Za-z0-9._-]{0,120}\.(webp|png)$`.
   Anything else exits 2. That rules out `..`, schemes, queries, other folders
   and other hosts, because the host is never taken from input.
3. **Cache hit.** If `$CACHE_DIR/previews/<basename>` is usable (a regular
   file, not a symlink, owned by the user, non-empty, within the ceiling) and
   its magic bytes check out, print it and exit 0. File names change when
   images change, so a hit is never stale.
4. **Download.** Otherwise run `curl -fsS --proto '=https' --tlsv1.2 --max-time 15 --max-filesize $PREVIEW_MAX_BYTES`
   against `https://plugins.omarchy.org/<relpath>`, into
   `mktemp -p $CACHE_DIR/previews`. `PREVIEW_MAX_BYTES` is 2 MiB.
5. **Verify.** The size must be greater than 0 and no more than the ceiling,
   and the magic bytes must be RIFF at offset 0 with WEBP at 8 (WebP), or
   `\x89PNG\r\n\x1a\n` (PNG). The format must also match the extension.
   Anything else is deleted, exit 3.
6. **Keep.** `mv -f` into place (atomic), then prune: if `previews/` passes
   50 MiB, delete the oldest files by modification time until it is under.
   Print the path.

The directory is created with `chmod 700`, like the catalog cache. Two
functions are split out so the test can call them: `preview_path_ok <relpath>`
and `preview_file_ok <file> <ext>`.

### `Model.js`

- `parseRows` keeps `preview` only if it matches the same path pattern.
  Otherwise the field is `""`.
- `previewArgv(root, relpath)` returns
  `[BASH, root + "/lib/catalog.sh", "preview", relpath]`, or `null` for an
  empty or invalid path.
- node tests:
  - a valid path passes;
  - these are rejected: `../x.webp`, `https://evil/x.webp`,
    `assets/img/plugins/x.webp?y`, `assets/img/other/x.webp`,
    `assets/img/plugins/x.svg`;
  - the argv is absolute.

### `BrowserState.qml`

- New properties: `previewFor` (a plugin id), `previewPath` (a local file, or
  `""`) and `previewing`.
- `preview(row)`:
  - it starts one `Process` for a row with a preview;
  - if another fetch is running, the newest request is queued, as the audit
    does;
  - when the fetch exits, it sets `previewPath` only if the exit code is 0 and
    stdout is an absolute path under the cache directory, and it leaves
    `previewPath` empty otherwise;
  - errors are not shown. The intent asks for "no image", with at most a quiet
    note.
- `BrowserView.openDetails` calls it next to `BrowserState.audit`.

### `BrowserView.qml`

At the top of the detail column there is one `Image`:

```qml
Image {
  visible: status === Image.Ready && root.selected && BrowserState.previewFor === root.selected.id
  source: visible || status !== Image.Null ? (BrowserState.previewPath ? "file://" + BrowserState.previewPath : "") : ""
  sourceSize: Qt.size(720, 405)   // decode is bounded, whatever the header claims
  width: parent.width; height: visible ? width * 405 / 720 : 0
  fillMode: Image.PreserveAspectFit
  asynchronous: true; cache: false; smooth: true
}
```

The final code keys `source` on `previewFor === selected.id`, so switching
plugins never shows the previous image. It takes no space until it is ready,
so text-only plugins look exactly as they do today.

### Docs

The README's panel section says:
- the preview comes from plugins.omarchy.org, only for the plugin you open;
- how it is checked (host, path, size, magic bytes);
- that `"previews": false` in `config.json` turns it off.

CHANGELOG 0.5.0, and the manifest version goes to 0.5.0.

## Alternatives rejected

- **The shell's `Image` loading `https://` directly.** The shell would decode
  unverified bytes straight from the network, with no size ceiling or type
  check. That is the thing the intent rules out.
- **Pre-fetching every thumbnail.** That is 3379 requests (about 70 MB) and
  tells the site nothing useful. The intent says only what you open.
- **The 1600×900 image, or an enlarge key.** It was decided at approval to
  leave both out.
- **A manifest setting or shell.json setting for the off switch.** The gate
  belongs where the network is. The script reads `config.json`, the file that
  already holds this plugin's other switch, so the CLI and the panel obey the
  same setting.
- **Time-based cache expiry.** The file names are content-specific, so expiry
  would only re-download identical bytes.

## Risks

- **A decoder vulnerability in libwebp.** It is mitigated, not removed:
  - a fixed host;
  - a path allowlist;
  - a 2 MiB ceiling;
  - a magic-byte check;
  - decoding bounded by `sourceSize`;
  - an off switch.

  The residual risk is a malicious file served by plugins.omarchy.org itself.
  That is the same trust root as the catalog, and the README says so.
- **An image appears for the wrong plugin** after quick navigation. This is
  prevented by keying on `previewFor`; the desktop check covers it.
- **The flake package.** No new files, so the file list does not change.
  `checks.default` still covers it, and the pacman/yay grep still passes.
  Checked in the plan.

## Verification

- `tests/preview.sh` (new, no network):
  - `preview_path_ok` accepts the real hyprmoncfg path and rejects the five bad
    shapes;
  - `preview_file_ok` accepts a real WebP and a PNG fixture, made with
    `printf` magic headers;
  - it rejects a text file renamed `.webp`, an empty file, a file over the
    ceiling, and a PNG named `.webp`;
  - with `"previews": false` in a temporary `XDG_CONFIG_HOME`, `preview`
    exits 4 without calling curl, shown by a `PATH` with no curl;
  - it is mutation-checked.
- `tests/model-check.mjs`: `previewArgv` and the `parseRows` preview cases.
- `tests/catalog-list.sh`: the `preview` field in the projection.
- **Live, once:** `bash lib/catalog.sh preview assets/img/plugins/5-crmne-omarchy-hyprmoncfg-card.webp`
  prints a cache path. `file` says WebP 720×405, and a second run is a cache
  hit, with no network, checked by timing or `strace -f -e connect`.
- `nix flake check` passes, and `omarchy-plugin-validate .` passes.
- **Desktop (the next razer grant):**
  - opening hyprmoncfg shows its screenshot above the description;
  - a plugin without a preview shows no box;
  - quickly switching between plugins never shows the wrong image;
  - with previews off, no image appears.
